# 资产归口制（2026-11-18）

## 一、事故与本轮结论

真机事故：董事会要「更新软件、修 bug」，CEO 派了两张卡 —— 维护代码给工程执行，更新代码给执行岗。
执行岗改完 → CEO 验收 → 卡直接 done。工程执行（代码仓库的台账主人）全程不知道这件事，
结果代码没提交、也没推送 GitHub。

这不是分工错。CEO 有权把活直接派给执行岗（灵活处置），错在流程里**只有一个关单条件**：
「交付验收通过」。代码改得对不对有人看，东西进没进仓库没人看。

本轮制度结论（董事会已认可）：

1. **指挥线不变**：谁派活谁验收、谁收汇报。CEO 直派执行岗，交付验收仍然是 CEO。
2. **新增归口线**：代码仓库归工程执行；工程执行只确认「变更是不是入库了、是不是推送了、或明确无需变更」。
3. **两个条件都齐才关单**：交付验收 + 归口回执。缺回执时卡停在 `in_review`，标「验收通过 · 待归口」。
4. **不搞一刀切**：不要求所有工程活必须回工程执行，也不让执行岗自己 push。
5. **按「动不动资产」触发**，不按「是不是技术活」触发：只读排查、一次性脚本、不入库产物不触发归口。

## 二、规则细则

### 触发条件

同时满足才派生归口核对卡：

- 产物类型是 `managed-code`（受管代码）；
- 卡上登记了 `repo`（仓库台账里存在）；
- 执行人不是这个仓库的归口人（`repos[repo].reviewer`，缺省 `artifacts.defaultReviewer`）；
- 这张卡还没有归口回执（`assetAck != done`）。

`config.artifacts.requireAssetAck = false` 可整体关闭（应急开关，不建议）。

### 关单双条件

```
交付完成
  → 验收（派单人 / 董事会 / 机器验收）
      ├─ 不通过 → 打回执行岗（原有逻辑）
      └─ 通过 → 检查归口
            ├─ 需要归口 → 派生「归口核对」卡给仓库主人
            │     父卡：in_review，assetAck=pending，assetOwner=工程执行
            │     归口卡 done → 父卡 done（收账落盘）
            │     归口卡 blocked/cancelled → 父卡 in_progress + 打回执行岗
            └─ 不需要 → 直接 done（原有逻辑）
```

所有「通过即完成」的入口都走同一个出口 `finalizeAccepted()`：
`reviewTask`、CEO review、董事会审批通过、机器验收、直接落盘、审批流验收。
任何一条漏掉都会重新打开「CEO 验收绕过仓库主人」的口子。

### 归口核对卡不是交付卡

- 它只核对父卡的 diff / 产物清单 / 工作区状态；
- 正确 → 提交并推送（遵守仓库 `allowPush` 策略）；
- 无需入库 → 写「无需变更：依据」；
- 改动不对 / 夹带无关修改 → 不重构，写 `failed` + 理由，父卡打回执行岗；
- 它的承接人就是资产主人，所以 `handoff=land`、`allowSelfLand=true`，回执不需要再拉 CEO 审一轮。

### 执行岗的弹性

- 小改（≤1 文件 / ≤40 行、不动接口、不新增依赖）可以自己做，但交付必须写清改过的文件清单，归口由引擎自动派；
- 大改（跨文件 / 跨模块 / 动接口 / 新增依赖 / 多产物）先出方案，退回上级或派给下级，不自己啃完；
- 任何情况不自行 `git commit` / `git push`（凭据与仓库责任都不在它手里）。

## 四、兜底与异常

| 情况 | 行为 |
| --- | --- |
| 归口卡跑完 done | 父卡自动 `assetAck=done` → `done`，落项目记忆与产物 |
| 归口卡 blocked / cancelled | 父卡 `assetAck=failed` → `in_progress`，向执行岗发 rework 事件，理由写明「归口没过」 |
| 归口卡被删 / 丢失 | 父卡重试验收时 `openAssetAckCard` 会按 `assetAckTaskId` 找不到就重建，不会永久卡死 |
| 归口人席位异常 / 离线 | 归口卡走正常补偿与上报链（L1/L2/L3），最终由 CEO 处置；不额外造一套旁路 |
| CEO 忘写 repo | 归口不触发，但提示词已把「代码卡 repo 必填」写成硬要求；后续可加「产物路径落在 repo 目录」自动探测（本轮未做） |
| 归口回执迟迟不来 | 卡在看板显示「待归口」，可按「重派」手动踢；长时间停滞由既有看门狗上报上级 |

## 六、设计边界（明确不做）

- **不**强制所有工程任务回工程执行转包 —— 会把 CEO 的灵活处置能力废掉；
- **不**让执行岗自己 commit/push —— 越权，且凭据不在它手里；
- **不**只靠提示词不加硬校验 —— 大模型会漂移，必须有状态机闸；
- **不**把归口卡做成第二张交付卡 —— 它只核对落地，不重做实现。
