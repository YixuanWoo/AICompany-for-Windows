# 总经理会话复用：所有工作共用一个会话

> 2026-11-16 晚。目的只有一个：**让按量计费的席位命中缓存，省钱。**

## 一、以前为什么不省钱

dsh 那个插件（`integrations/dsh/ceo-webhook`）本来就支持复用会话：投递时带上 `sessionId`，它就 `resume` 同一个会话；不带，就按任务号新建一个。

而我们的 adapter 以前**从来不带**：

```js
// 旧代码
await call('/aiceo/api/task', { taskId: key, prompt, cwd });   // 没有 sessionId
```

于是每一张卡、每一轮（拆解一次、验收再一次）都是全新会话。系统提示词、员工名册、项目清单、记忆摘要——这些占大头的前缀，**每一轮都重新付一遍全额**。

按量计费的席位，缓存命中和不命中是两个价；一轮省一点，一天几十轮就是真钱。

## 二、现在怎么做的

| 之前 | 现在 |
|---|---|
| 按「卡号-轮次」新建会话 | **所有工作共用一个会话**，只有换新时才变 |
| 拆解 / 验收各一个上下文 | 同一个上下文，验收时它记得自己当初为什么这么拆 |
| 缓存 0 命中 | 前缀稳定 → 命中 |

三条约束，都在代码里：

1. **一个会话不能并发跑两轮。** 服务端按 `sessionId` 反查任务来收文本，两个任务同时挂一个会话会串台。所以 adapter 里加了按会话的排队（`withSessionLock`）：上一轮没结束，下一轮等；上一轮失败也放行，不会把会话永久堵死。
2. **会变脏、会变贵。** 所以有 `warnTurns`（默认 30 轮提醒）和 `maxTurns`（默认 60 轮自动换）。
3. **换会话不是删历史。** 旧的那段会留在会话文件的 `previous` 里（起止时间、跑了多少轮、为什么换），只是不再往里追加。

## 三、你能控制的三件事

**① 看板上看得见。** 「席位与配额」顶上多了一行：

> 总经理会话 `202611161212-bqrh`｜已 12 轮｜开了 3 小时 · 近一次 T-xxxx
> 共用会话是为了命中缓存省钱；到 30 轮提醒，60 轮自动换。　［新建会话］

**② 一句话就能换。** 点「新建会话」→ 确认 → 下一轮起用新会话，**正在跑的卡不受影响**（adapter 排队，不在投递中间掐断）。审计记 `ceo_session_reset`。

**③ 到点会提醒。** 第 30 轮时发一条通知（桌面气泡 + 看板简报），同一个档位只提醒一次（记在会话文件的 `warnAts` 里，重启不重发）。第 60 轮自动换，也留痕。

## 四、配置

`config/company.prod.yaml`：

```yaml
interaction:
  ceoSession:
    reuse: true     # false = 回到「每轮新会话」的旧行为（排查用）
    warnTurns: 30   # 到这个轮次提醒换新
    maxTurns: 60    # 到这个轮次自动换新
```

不写也有默认值（同上）。豆包（GUI 席位）不受影响——它用的是桌面窗口，没有会话这个概念。

## 五、会话文件在哪、怎么手动清

`work-prod/sessions/ceo.json`

```json
{
  "sessionId": "ceo-202611161212-bqrh",
  "startedAt": "2026-11-16T12:12:46.994Z",
  "turns": 12,
  "lastUsedAt": "...",
  "lastTaskId": "T-xxxx",
  "previous": { "sessionId": "...", "closedAt": "...", "turns": 28, "reason": "轮次到上限" },
  "warnAts": [1]
}
```

删掉这个文件 = 下次唤醒自动开一个新会话（和点按钮等效，但不会留审计）。建议还是点按钮。

## 六、提示词里补了一句

共用会话意味着 CEO 会看到自己前几轮的判断。不说清的话，它会把历史当成「还没派」，重派一遍。所以提示词开头加了一段：

> 【会话】你和董事会的往来都在这一个会话里（为了命中缓存、省额度）。
> 你看到的历史是你自己前几轮的判断，那是记录，不是新指令：这一轮只处理下面这张卡，不要复述、不要重派已经派过的活。
