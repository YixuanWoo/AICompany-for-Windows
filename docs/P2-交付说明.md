## 一、先回答你最关心的三个问题

| 你问的 | 答案 |
|---|---|
| 「打算部署到真服务器上吗？」 | **不部署，现在也不做这件事。** P2 的「服务器化」指的是**代码分层**：把「发号施令的控制面」和「在你电脑上真正干活的 agent」拆开，不是说要买台服务器放上去。同一套代码，绑 `127.0.0.1` 就是单机，将来改个配置放远程也能跑，**但现在一步都没往外搬**。 |
| 「本地演示保留吗？开源要考虑没服务器的人」 | **保留，而且是一等公民。** 默认 `npm start` 就是本地 inline 模式，不配任何环境变量、不用 Docker、不用 WSL2、不用 Redis、不用消息队列、不联网、不烧额度，假 agent 就能把整条链路演完。P2 新增的 bridge 是**可选的第二形态**，用环境变量 `AICOMPANY_DISPATCH_MODE=bridge` 才开。 |
| 「Windows 本地优化呢？」 | **按你说的，本轮不碰。** 打包成 exe、开机自启、托盘、权限、安装向导这些留到后续专门的 Windows 专项。P2 只负责「整个工具先跑通」。 |

一句话记法：**P2 加了一条新路，没拆掉原来那条路。**

## 二、这步到底是咋回事（大白话版）

打个比方，P1 的公司是「老板、员工都坐在同一间办公室，调度室直接拍桌子叫人」。P2 做的是把它改成「调度室 + 外勤」两拨人：

| 公司里的东西 | 代码里叫啥 | 干什么用 |
|---|---|---|
| 调度室的待领窗口 | `/api/bridge/inbox` | 活先摆在这儿，谁有空谁来领 |
| 领活登记本 | `leaseToken` / checkout | 一张活同时只能被一个人领走，抢不到就返回 409 |
| 外勤打卡 | heartbeat | 每隔一会儿报个到；没打卡就说明人不在，活先存着 |
| 断网 30 分钟 | 离线队列 | 人不在这期间新活全排队，一次都不叫醒，开机后按顺序补领 |
| 每天固定要干的活 | `RecurringJob` / `Cycle` | 到点自动生成一张**新**任务卡，绝不把上一轮改回「未完成」 |
| 上一轮没解决的遗留问题 | `carryOver` | 自动写进下一轮的输入里，还记着「已经挂了几轮」 |
| 闹钟 | scheduler（`setInterval`） | 控制面自己算触发点，不装 pm2、不写系统 cron |
| 值班日志 | `logger.js` | 按天一个文件，**只追加，绝不自动删** |

最要紧的两条：

1. **一张活不会被两个人干两遍**：靠数据库里一条带条件的更新语句，10 个人同时抢，只有 1 个抢得到。
2. **循环任务不会「改旧账」**：每轮都是一张全新的卡，上一轮的结论留成历史，新卡带着旧结论继续干。

## 三、为什么要做这步

P1 只证明了「一条需求能自动办完」。但要开源给别人用，还差三件事：

- 有人想把控制面放在一台常开的机器上、agent 跑在自己的笔记本里 → 需要拉模式 + 领取互斥 + 断线补投。
- 日常活儿是「每天巡检一遍」「每周出一份简报」，不是一次性需求 → 需要循环引擎，还要处理「停机错过了 3 个触发点怎么办」「上一轮没干完又到点了怎么办」「连着失败三轮要不要自动停」。
- 项目要能给别人直接跑 → 不能依赖 pm2、systemd、cron、Docker 这些得先装一堆东西的东西。

## 四、具体改了什么

### 4.1 新增文件

| 文件 | 作用 |
|---|---|

| `src/bridge-api.js` | 统一 API 下的 `/api/bridge/*` 八个端点（不是另一套协议） |
| `src/bridge.js` | 本机 bridge 客户端：心跳 → 拉 inbox → checkout → 调 adapter → 回写报告 |
| `scripts/bridge.js` | **可以直接跑的 bridge 命令**（`npm run bridge`），地址 / 席位 / adapter 命令全走环境变量 |

| `src/scheduler.js` | 内置定时例程，时间可注入，`timer.unref()` 不拦着进程退出 |
| `src/ops.js` | 运维席位命令构建器（local / ssh）+ 硬编码主机路径检查 |
| `src/logger.js` | 结构化 JSON 日志，按天轮转，**不自动删除任何文件** |
| `scripts/daemon.js` | 可选的零依赖崩溃重启守护（替代 pm2 那部分） |
| `tests/p2.test.js` | 32 条 P2 验收测试 |
| `docs/P2-交付说明.md` | 本文件 |

### 4.3 验收前修掉的 6 个坑

| 坑 | 不修会怎样 | 怎么修的 |
|---|---|---|
| 轮次收账后，失败/跳过仍被当成「上一轮没干完」 | 连败 3 轮自动暂停这条根本测不过，第 2 轮就被 overlap 拦住 | `activeCycle` 只认未收账状态，`done/failed/cancelled/skipped` 都算已收账 |
| `event` 型触发没有 rrule，却被算成「每天触发」 | 事件型任务会被闹钟反复唤醒 | 无 rrule 时 `nextFireAt` 保持 `null`，不吃 cron 时钟 |
| `carryOver.ageCycles` 每轮都从 0 重新数 | 「这个问题挂了 3 轮」永远显示成 1 轮 | 从上一轮历史按 id 继承再 +1 |
| bridge 模式下 CEO 验收被「bridge 不在线」拦掉 | 完成报告回写后任务永远卡在 `in_review`，链路跑不通 | 在线检查只约束「派卡」类唤醒；验收 / 升级是控制面内部决策，走控制面自己的 adapter |
| 收账后本轮任务卡还是 `todo` | 留下一张永远没人领的孤儿卡 | 收账时同步把卡收口为 `done` / `blocked` 并写审计 |
| bridge API 的时钟写死 | 「断机 30 分钟」「租约过期」没法做确定性验收 | `createBridgeApi` 加 `now` 注入，心跳 / checkout / 回写校验全用同一时钟 |

## 七、怎么自己跑起来看

### 形态 A：自己电脑上直接开张（推荐，零配置）

```bash
cd D:\开源\AICompany
npm start
# 浏览器打开 http://127.0.0.1:3100
```

不配任何环境变量也能跑，会自动用本地假 agent 演示，不联网、不烧额度。

### 形态 B：控制面 + 本机 bridge 分开跑（可选）

```bash
# 终端 1
AICOMPANY_DISPATCH_MODE=bridge npm start

# 终端 2（不设 AICOMPANY_BRIDGE_CMD 就用本地假 agent 演示）
npm run bridge
```

跨机器时给两边都设 `AICOMPANY_BRIDGE_TOKEN`，控制面地址用 `AICOMPANY_BRIDGE_URL`，席位用 `AICOMPANY_AGENT_ID`，真实 agent 命令用 `AICOMPANY_BRIDGE_CMD`。想「拉一次就退出」用 `AICOMPANY_BRIDGE_MAX_LOOPS=1`。

### 形态 C：崩溃自动重启（可选）

```bash
npm run start:daemon
```

停止服务：在运行服务的终端按 `Ctrl + C`。真实配置与 `.env` 已被 `.gitignore` 排除，不会进仓库。
