# 升级去向：从「换个席位重做」改成「上级先巡检」

> 2026-11-24 立。起因是 T-5457e8a0（批量文档标注，cli-exec）：CLI 明显在干活，卡却被判「无产出」→ 重派 → 再打回 → 转给 engineering，最后由人手动中断。用户当场提的方案是"上级接手时不是重做，而是检查下级到底有没有在动"。本文把这件事定下来，并列出两个待做步骤。

## 二、三个误判点

### 1. 证据层只盯任务目录 `output/`（已修）

派活提示词要求产物直接写项目交付目录（`projects.<id>.rootDir`），证据层却只在 `work-prod/tasks/<taskId>/output/` 里找新鲜文件。output/ 常空 → L2 恒空 → 到点一定判死。

修法（2026-11-24 已上线）：

- `src/evidence.js` 的 `probeRun` 增加 `extraDirs`，扫项目交付目录的 mtime；
- `src/engine.js` 抽出 `projectWriteDirOf(config, task)`，派活与证据层共用同一口径；reconcile 时把交付目录传进去；
- 证据种类新增 `artifact-project`，看板显示「项目产物」；
- 新增 `tests/evidence-project-artifact.test.js`（3 条）。

### 2. 报告 `status=failed` 缺 reason 被整份打回（未修，登记待办）

校验规则是「failed 必须带 reason」。agent 交了一份 `status=failed` 但没写原因的报告，被整份拒；同因再犯一次 → 这趟 run 记 `failed`，卡按 rework 转上级。

问题在于：**「报告不合格」和「agent 自报失败」被混成一件事**，而且两次同因就判死，等于把"它自己说没干完"升级成"换个席位重做"。

方向（未定，需要拍板）：

- 缺 reason 时补一条默认说明收下，按"未完成"回 `todo` 重派，而不是整份丢；
- 或把"agent 自报 failed"单独记一种结果，不进"报告不合格"的两轮计数；
- 无论哪种，都要保住「不许把半成品当交付」这条底线。

### 3. 看板 L1 叫「已送达」（已修）

`dispatch.json` 只证明进程/窗口起来了，不代表 agent 收到或开工。现口径：L1 = 已启动，5 分钟无产出痕迹标黄「未开工 N 分」。

## 三、方案：上级接的是巡检，不是重做

好消息是底子已经有：处置卡（`openEscalation`）的提示词写着「不许你自己动手重做这张卡的活」，要求给返工 / 改派 / 上报三选一，处置完原卡自动回到执行人。真正缺的是**"先判断它到底在不在动"这一步**。

### 第一步：处置卡加巡检判据（2026-11-25 已落地）

在处置卡 instructions 里加了一段「第一步：先判它到底在不在动」（`src/engine.js` `openEscalation`）：

- 三条判据：
  1. 交付目录有没有本轮新文件（mtime 晚于本次派单）；
  2. 进程有没有在烧 CPU（隔十秒看两次，有增量就是在跑）；
  3. CLI 有没有在输出（`cli-output.log` 尾部）。
- 结论模板：
  - 任一成立 → 写「判为在动：让它继续」，并写清依据；**不改派、不改验收条件、不自己动手**；
  - 全都不成立或查不到 → 返工（写清改成什么）/ 改派（给谁）/ 上报总经理。
- 与现有机制自洽：结论无论哪种，处置卡完成后 `resumeParentAfterEscalation` 都会把原卡送回**同一个执行人**
  （assignee 不变、attempt 清零），已写下的产物还在 —— 所以「让它继续」= 同一席位续干，不是换人重做。
- 仍保留底线「不许你自己动手重做这张卡的活」，以及「处置卡必须给明确结论、不许停在原地」。

### 第二步：升级卡自动附现场（待做）

判死前把现场写进证据包，上级不用自己找：

- 交付目录绝对路径 + 最近改动时间 + 最新文件名；
- 进程 pid / 相邻采样 CPU 差分 / 是否有网络连接；
- CLI stdout 尾 100 行（桥接先落 `cli-output.log`，目前只存在内存里）。

## 四、边界（防新坑）

- **不新建"巡检任务"类型**：用现有处置卡承载，两套语义并存必打架。
- **卡片不消失**：非终态卡永远留在看板；处置卡挂着时原卡 `blocked`，处置完自动回执行人。缺的只是看板一句话「已转上级巡检（处置卡 X）」。
- **并发不冲突**：全局 `maxConcurrent: 3`，同一张卡永远只允许 1 条 run；巡检卡与原卡是两张卡、两个名额。真正抢的是额度和同一台机器同时几个 CLI 会话。
- **巡检不做定时轮询**：只在"快判死"时触发一次，避免额度黑洞。
