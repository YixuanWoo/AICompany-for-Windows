# 计划与定时任务（看全部未来要触发的活）

> 2026-11-17 需求演进：
> ① 任务到点再传给公司（避开白天用机 / 压到低峰计费窗），多个排班按顺序、到点忙就等；
> ② 公司**自己**也要能排一次性定时（例如「视频发完第二天复盘」，只做一次，不是每周重复）；
> ③ 看板上要**有一个地方**能看见全部未来会被触发的任务，否则「公司到底设置成功了没」无从核对。
>
> 结论：调度没有新写。全部复用循环引擎（`src/recurring.js` + `src/rrule.js` + `src/scheduler.js`），
> 本次只加了三样东西：看板「计划」标签页、`src/schedule-request.js`（构建一次性排班的唯一入口）、
> CEO 排班建议支持 `at`（一次性）。

## 一、看板「计划 · 未来要触发的」（默认第一个标签页）

打开 http://127.0.0.1:3100/ ，**默认就落在「计划」页**，里面是一张总表，一处列全三类东西：

| 表里的东西 | 谁排的 | 说明 |
|---|---|---|
| 循环任务 | 总经理提 → 你批 | 每周 / 每月反复跑（体检、巡检、清理、简报） |
| 一次性定时 | 你排的，或总经理提的 | 到点做一次，跑完**自动结束**，不会每周重复 |
| 等你批的排班 | 总经理提的 | 标「等你拍板」，批了才真进调度器 |

每条都显示：状态（会触发 / 已暂停 / 已跑完）、**只跑一次**或**循环**的标记、下次触发时间、
已跑几轮（一次性显示 `1/1`）、谁干、归哪个项目、谁验收、干什么的一段摘要。
排序规则：**按下次触发从近到远**，已暂停/已跑完的沉到最后——不会因为状态不同就把计划藏起来。
每条右边三个动作：**先别跑**、**恢复**、**现在就跑一次**。

排一条新的：同一页下面「定时下达 · 到点再传给公司」——写一句需求，选日期（**留空＝最近一次该时刻**，
过了就排明天）和时间（默认 02:30），点「排上」。高级项可指定交给谁 / 谁验收 / 归属项目。

## 二、公司自己排一次性定时（CEO 写 at）

总经理在拆活时就能提「到点做一次」，走的是和循环任务**同一条审批通道**，CEO 只提、不自建：

```json
{"recurringSuggestion":{"title":"复盘第 12 期视频","at":"2026-11-18 21:30",
 "project":"频道id","assignee":"doubao","instructions":"拉完播率/评论关键词/涨粉数，出一份复盘",
 "acceptance":["复盘落在 output/","写清下一期改的三件事"],"reviewBy":"ceo","reason":"只做一次，等数据积一天"}}
```

- **判定口径**：同一件事以后还会反复做 → 写 `rrule`；做一次就完、只是要等时机 → 写 `at`；
- `at` 支持 `"2026-11-18 21:30"`（钉在那天）和 `"21:30"`（最近一次该时刻）；
- 审批单上是人话：标题「定时任务申请（只跑一次）：…」，正文写「什么时候跑：只跑一次，2026-11-18 21:30」，
  不再拿 rrule 冒充节奏；
- 通过后注册成 `SCH-*` 的 job：`maxCycles: 1`、`overlapPolicy: 'queue'`、`misfirePolicy: 'run_once'`；
- **跑完当场收工**：`fire()` 在 `maxCycles` 触顶时直接把 job 标 `ended`、`nextFireAt` 清空，
  不会留一条「active · 下次明天」的假计划骗人。
- CEO 的提示词（`src/adapter-webhook-exec.js`）已写明这条口径与写法，不用你每次手写。

## 三、命令行（等价入口）

```powershell
npm run schedule -- add "把第三批文档处理完" --at 02:30 --project demo
```

## 命令

| 命令 | 作用 |
|---|---|
| `npm run schedule` | 列出已排的（下次触发时间 / 状态 / 交给谁） |
| `npm run schedule -- add "<需求>" --at <时间>` | 排一条，只跑一轮 |
| `npm run schedule -- batch queue.txt` | 按文件顺序排一批，每行 `时间 \| 需求 \| 项目` |
| `npm run schedule -- pause <jobId>` | 取消（引擎没有删除，只有暂停） |
| `npm run schedule -- resume <jobId>` | 恢复 |
| `npm run schedule -- fire <jobId>` | 不等时间，立刻试跑一轮 |
| `npm run schedule -- add ... --dry` | 只打印将要提交的 JSON，不真排 |

选项：`--project`（归属项目，继承规范与交付目录）、`--to`（交给谁，默认 ceo）、`--review`（谁验收，
默认不写＝按发布者直接落盘）、`--difficulty`、`--accept "条件1;条件2"`、`--tz`（默认 Asia/Shanghai）、
`--gap-min`（batch 里同一时刻自动错开的分钟数，默认 10）。

时间写法：`02:30`（最近一次该时刻，过了就排明天）或 `2026-11-18 02:30`（钉在那一天）。

## 四、语义（都是引擎既有能力）

| 你的要求 | 落在哪 | 怎么实现 |
|---|---|---|
| 到点才传 | `src/rrule.js` + `src/scheduler.js` | 每 15 秒 tick 一次，到点才算触发点 |
| 只跑一次 | `termination.maxCycles = 1` | rrule 不支持 COUNT，用这个把 job 在首轮后收口；跑完即 `ended` |
| 时间到了但正忙 → 等 | `overlapPolicy: 'queue'` + 唤醒闸 | 自己上一轮没完时不重复建卡；卡建好后唤醒被并发/冷却挡住，留在 todo 等补投 |
| 错过了（机器睡着） | `misfirePolicy: 'run_once'` + 宽限 12 小时 | 醒来只补最近一次，不补一串 |
| 多个排班按顺序 | 时间本身 + `planBatch` 错开 | 同一分钟齐发会同时进队列，所以 batch 默认每条错开 10 分钟 |

## 六、需要注意

1. **顺序不是全局互斥锁**。两排班同一分钟到点、又都交给 CEO 时，CEO 侧可能同时拆两张
   （`runPolicy.maxConcurrent: 2`）。要严格串行，用 `batch`（自动错开）或把 `runPolicy.maxConcurrent` 临时调成 1。
2. **定时下达的是「卡」不是「额度」**。到点建卡后仍走正常额度与闸门；夜间跑不吃白天额度，但会吃当天额度，
   `quotaDaily` 太小时夜里可能因额度不足被拦（`gate_blocked`），需要的话把席位额度调高。
3. **低峰计费窗要自己对齐**。引擎只管「几点几分」，不认服务商的峰谷；把 `--at` 对准低峰开始时间即可。
4. **暂停是逐条的**。想「今晚整体停机」用顶部的 GUI 暂停键（引擎总开关），不是逐条点「先别跑」。
5. 会话里的 `doubao-cron-scheduler` 是另一套（提醒我自己），与公司内部排班无关，别混用。
