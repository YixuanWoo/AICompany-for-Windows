## 二、致命问题：项目还没批，活已经跑完了

### 根因（两层，都确认了）

1. **项目判定失败只降级，不阻塞**
   `assertProject` 报"项目不存在"时，引擎只写一条 `project_rejected` 审计，
   然后 `childProject` 保持 `null`，**卡片照跑**。
   于是 CEO 说的"归 demo-editor"变成了"不归属任何项目"。

2. **建项目审批单不拦父卡**
   `projectSuggestion` 只是"顺手"出一张单，父卡继续拆卡、继续执行。
   董事会慢一步点通过，活早就干完了——审批对**当轮完全无效**。

3. **经验和交付都以 `task.project` 为前提**
   `flushProjectMemory` / `deliverAccepted` 第一行就是 `if (!task?.project) return null`。
   `project` 是 null → **项目记忆一条不写、交付一份不落**。
   这是你说"经验好像都没写进项目"的**结构性原因**。

### 修法：项目闸（等审批，不许先跑）

- 卡片里**显式写了**一个不存在的项目 id → 父卡立刻转 `awaiting_decision`，
  **一张子卡都不建**，并确保有一张待批的建项目单。
- 董事会**通过** → 建项目，并把父卡放出来重新拆（唤醒理由 `decision`，挂起态只认这个出口）；
  这次卡片上的项目真实存在，规范、记忆、交付全部有着落。
- 董事会**拒绝 / 要求重写** → 父卡同样放出来，按一次性任务跑（产物只留在公司），
  且同一 id 不再重复出单，不会把链路堵死。
- 只拦"显式指了不存在的项目"；只是"以后可以单开一个"的建议**不阻塞**当前工作。

提示词同步写死：**不许为了先跑起来就把 project 留空**——那样产物和经验全落不到项目里。

### 更正：经验其实是有的，是我第一次查错了字段

我第一次查的是 `completion.json` 顶层的 `c.lessons`（这个字段不存在），据此说「豆包压根没交经验」——**这是错的**。

实际位置在 `usage.memoryFeed.lessons` / `nextHints`：4 张卡**各有 8 条教训 + 8 条下次提示**，内容非常具体，例如：
> 「测试项数以测试程序最后一行『全部通过 ✓（N 项）』为准；源码里 Check( 调用因循环/跨行计数与运行项数对不上，别拿源码计数当基线。」

所以那 4 张卡的经验没进项目，**唯一原因就是 `project=null`**（上面第 3 条根因），不是员工没交。
补挂后已全部写进 `work-prod/projects/demo-editor/knowledge/memory.jsonl`：4 条记录，每条 8 教训 + 8 提示 + 产物清单。

仍然保留一处改进：草稿报告里 `lessons` / `nextHints` 从"可选"改成**明确要求至少写一条**
（确实没有就写 `[]`，别编）——把"最好写"变成"默认写"。

## 三、这次新增的：CEO 能排班，但必须董事会批

| 环节 | 做法 |
|---|---|
| CEO 输出 | 契约新增 `recurringSuggestion`（单条）/ `recurringSuggestions`（数组，最多 3 条） |
| 谁填什么 | CEO 只填人能看懂的：标题、节奏（rrule）、每轮干什么、怎么算干完、派给谁、归哪个项目 |
| 协议字段 | 其余（kind / termination / overlap / dedupe…）由控制面补齐，不让它背 schema |
| 承接人 | 走 `resolveChildSeat`：CEO 点自己也会被改派执行席位（严禁自干的三道闸之一） |
| 归属项目 | 必须真实存在；不存在直接拒单，不让循环卡落到野地里 |
| 董事会议长啥样 | 审批卡显示：**节奏（人话）/ 每轮干什么 / 验收 / 谁干 / 归属项目 / 消耗 / 连续失败自动暂停** |
| 通过 | 才 `registerJob` 真正进调度器；不点通过，调度器根本不知道有这条 |
| 循环卡带项目 | **修了一个隐藏缺陷**：`recurring.js` 建卡时根本不写 `project`，协议也不允许 → 循环任务永远不认项目。已加协议字段 + 写入 + 引擎读取（`SELECT *` 自动带上） |
