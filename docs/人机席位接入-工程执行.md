# 把会话里的 agent 接成「工程执行」席位

## 一句话

给「人叫才醒」的 agent 开一个席位：**卡不进它的 Run，进它的队列**；它自己来领、自己交。

## 一、为什么不直接复用 bridge

`src/bridge.js` 是一个**常驻轮询进程**：心跳 → 拉 inbox → checkout → `adapter.execute()` → 回写。它默认「我一直在，有活就干」。

但会话里的 agent 不是这样：**它不在**。没人发消息，它就没有进程，没有 Run，没有心跳。如果照 bridge 那样把卡直派给它，结果是：

- 派活时它不在 → 白烧一次 Run（GUI 席位要抢键鼠、webhook 席位要真调模型）
- 或者卡卡在 `in_progress` 等一个永远不会来的报告

所以真正要解决的不是「怎么调它」，而是「**它不在的时候别调它**」。

## 二、复用了什么，新增了什么

| 部分 | 结论 |
|---|---|
| HTTP 协议（心跳 / inbox / checkout / complete） | **100% 复用** `src/bridge.js` 的 `request`，端点一个没改 |
| 租约（lease 独占、防重复领） | **直接复用**，只是加了续租 |
| `bridge.start()` 的轮询循环 | **不复用**——它要求常驻，而人机席位的本质是「不常驻」 |
| 派活机制 | **新增**席位级 `dispatch: pull`（原来只有全局 `dispatchMode: bridge`） |
| 续租 | **新增** `/api/bridge/renew`：干一张卡可能远超默认 5 分钟租期 |

新增的两个东西都很薄：一个字段、一个端点。

## 三、改了什么

### 1. 席位配置：`dispatch: pull`

```yaml
holders:
  - id: wb-agent
    name: WorkBuddy agent
    kind: external-agent
    adapter:
      type: seat          # 不是 mock：万一被误配成直派，会当场报错而不是假装干完

posts:
  - id: engineering
    title: 工程执行         # 岗位名：写代码 / 改配置 / 跑命令 / 查资料
    heldBy: wb-agent       # 担任者：会话里那个 agent
    capabilities: [execute]
    reportsTo: ceo
    dispatch: pull
```

`push`（默认）= 控制面直调 adapter；`pull` = 卡留队列，等本人来领。

引擎侧三处配套：

| 位置 | 行为 |
|---|---|
| `handleEvent` 的派活分支 | 看到 `dispatch: pull` → 写审计 `queued_for_pull`，卡保持 `todo`，**不启动 Run** |
| `runPolicy` | 加一道闸：拉模式席位任何时候拒绝被主动唤醒（防别的路径绕过来） |
| `reconcile` 心跳 | 跳过拉模式席位的卡——**「在等人领」不是「躺尸」**，否则每 60 秒刷一条无用的重投 |

### 2. 新增 adapter 类型 `seat`

```js
async execute(ctx) {
  throw new Error(`席位 ${ctx.agent?.id} 是拉模式（seat），控制面不该直调它；请把 dispatch 写成 pull`);
}
```

配对了永远不会被调用；配错了立刻炸。**绝不静默成功**——否则会得到一张「显示完成、其实没人干」的假卡。

### 3. 领取工具：`scripts/seat.js`

```bash
npm run seat -- --as engineering status    # 我在线吗、有几张等我
npm run seat -- --as engineering inbox     # 队列里都有什么（含完整任务指令）
npm run seat -- --as engineering claim     # 领最早一张（拿 lease，落盘到 work-prod/seats/<id>/current.json）
npm run seat -- --as engineering holding   # 我手上还有什么没交
npm run seat -- --as engineering renew --ttl 3600   # 长活续租
npm run seat -- --as engineering report --summary "一句话说清干了什么"
```

三道硬约束：

1. **一双手一张卡**：手上还有没交的，`claim` 直接拒（租约过期除外），免得两张同时占着手必然漏一张。
2. **交活必须写 summary**：空 summary 等于没交代，控制面拒收。
3. **产物清单由控制面口径算**：扫 `tasks/<taskId>/output/`，生成 `output/xxx` 形式的相对路径，和 `deliver.js` 完全一致——所以项目落盘、验收、报表全都认。

## 四、一个卡从派到完的完整路径

```
CEO 拆卡 → 指派给 engineering
  → 引擎发现 dispatch: pull → 审计 queued_for_pull，卡留 todo（不烧 Run）
  → 我被叫醒，跑 seat claim → checkout 拿 lease，卡进 in_progress
  → 我用 Bash / Edit / Read 干活，产物写 work-prod/tasks/<id>/output/
  → 租期快到了就先 renew
  → seat report --summary "..." → 带 lease 回写 completion.json
  → 引擎走正常验收（delegate 模式下 CEO 验收；direct 模式机器判）
  → 卡 done；产物按项目规范落盘
```

## 五、为什么没做成「无人值守」

理论上可以让 CLIC 无头跑（本机有 `@genie/agent-cli`，支持 `-p/--print` 和 `--acp`），spawn 一个子进程当 adapter。实测结论：

```
$ codebuddy -p "只回答两个字：收到" --output-format json
Authentication required. Please use /login command to sign in to your account
```

CLI 自己的日志写着 `Failed to read settings file for scope user: ENOENT`——**桌面版的登录态在 Electron 那边，CLI 拿不到**。要跑通得在那个终端里交互式登录一次，这需要人来做。

所以现在这条链路是「半自动」：

- 公司派活 → 卡排队（不会白烧）
- 我被叫醒时 → 一条命令领走、干完、交

**这不是缺陷，反而更省**：省掉的正是「没人在场时也自动跑一轮」的额度。

## 六、已知边界

| 边界 | 说明 |
|---|---|
| 我不能自己醒 | 没人说话我就不动。所以卡会在队列里等着，不会丢，也不会被硬派 |
| 一双手一张卡 | 我串行干活，不急的卡排队 |
| 租约默认 1 小时 | 超长任务要 `renew`；租约过了不续，控制面会认为这张卡没人管 |
| CEO 知道我适合什么 | 名册里 `工程执行` 这个岗位名就是给人的信号：要动代码 / 命令的活派这里，写文档翻译派 `执行`（豆包） |
