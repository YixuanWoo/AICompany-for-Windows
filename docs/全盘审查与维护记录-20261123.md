## 3. 第二轮维护（2026-11-23 晚）：除开源阻断外全部落地

触发：董事会明确要求「项目产物按项目目录与项目规则落盘，项目文件禁止进 `output/`；
`output/` 只放任务卡、说明、进度、完成报告等 AICompany 自己的文件」。

### 3.1 落盘改造（原 P0-1，已实施）

- 派活时引擎用 `resolveDeliverDir` 算出本单落点，注入 `ctx.project.writeDir`（绝对路径）。
  项目没配 `rootDir` 时为 null，提示词退回 `output/`，行为同旧版。
- 提示词口径改（GUI 两种模板 + CLI）：产物写项目落点，**项目产物禁止写 `output/`**；
  `output/` 只放任务卡相关文件；路径一律绝对路径。
- 完成信号改 **manifest 制**：`report.draft.json` 增加 `deliverables: [{path}]`（绝对路径）。
  控制面逐条亲自核验：绝对路径、在落点内、存在且非空、checksum 自算。
  有 deliverables 时**不再用「output/ 有没有文件」否决完成信号** —— 产物本来就不在 output/。
  这条遵守维护标准 §3：进度与完成分离，缺清单不等于判失败。
- `verifyReport` / `pollForReport` / `buildCompletionFromDraft` 增加 `writeDir` 参数；
  新增 `isInsideAllowedRoots`，旧 `isInsideOutput` 保留且行为不变。
- 交付分层：artifacts 全是绝对路径 → **in-place 只记账不复制**（台账 `mode: 'in-place'`，含 bytes/sha256）；
  相对路径（`output/...`）→ 仍走旧复制路径，老卡不受影响。维护心跳的「已交付」判断兼容 in-place。
- 产出心跳同时盯 `output/` 与项目落点（GUI adapter 与 CLI 桥接都改），采样上限 2000 个文件，
  防止大项目目录每 5 秒被全扫一遍。

### 3.2 配置死字段与规范噪声（原 P1-6 / P1-7，已实施）

- `yaml-lite` 支持纯标量列表项 —— `project.yaml` 的 `redlines` / `acceptance` / `memory.focus`
  以前一解析就抛错，项目规范根本无法结构化读取。
- `buildProjectContext`：`memory:` 段从「必须遵守」的规范正文剔除；`memory.focus` 单独成【项目焦点】
  必读段（董事会拍板：记忆量不大，全量读，不做分级检索）；`requireLessons: true` 变成提示词里的
  明确要求（软约束，不判失败）。
- 实测 demo 规范：focus 3 条正确注入，规范正文不再含 `memory:` 配置。

### 3.3 其它（已实施）

- `deliver-copy.js` 保留相对目录结构，含 `..` / 绝对路径的名字一律拒绝（原 P1-4）。
- CLI 提示词抽成 `src/cli-prompt.js` 纯函数，桥接只负责喂给 CLI；测试从源码断言改为真单测（原 P1-8）。
- 控制面日志：engine 新增可选 `log`，在派活 / 终态 / 重派 / 交付四类节点写；
  server 用 `src/logger.js` 落到 `<workRoot>/logs/engine/YYYY-MM-DD.log`（原 P1-9）。
- 项目记忆超量归档：`archiveMemoryIfNeeded` 把最老的挪进 `knowledge/archive-YYYY-MM.jsonl`
  （保留 `memoryLimit×2` 条；归档不是删除），引擎写完记忆后自动调用，归档留 `memory_archived` 审计（原 P2-10）。
- 空记忆软约束：最近 3 单 lessons/nextHints 全空时，提示词点名提醒（原 P2-12）。
