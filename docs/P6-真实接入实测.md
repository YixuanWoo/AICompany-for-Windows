## 3. 真机上才暴露的 9 个坑（全部已修 + 补了回归测试）

模拟驱动全绿、一接真窗口就连续失败三次，原因全在下面。

| # | 坑 | 表现 | 修法 |
|---|---|---|---|
| 1 | 派活前的环境检查没注入 `workRoot` | 审计报「任务根目录存在且可写：未配置 workRoot」，任务直接退回 `todo`，一张卡都发不出去 | `engine.wake` 里给 `testEnvironment` 传和真正派活同一份配置 |
| 2 | 阻塞结果里混进 `sessionParams` | 失败被报成「$.sessionParams: 不允许的多余字段」，真正的失败原因被吃掉 | `gui-adapter` 把 `sessionParams` 从 completion 文档里剥出来，只放在结果顶层 |
| 3 | 审计只记 `blocked` | 只写 `第 1 次：blocked`，为什么被阻塞查无可查 | 审计改为记录 `status：reason`（失焦 / 超时 / 环境不通过都能看见） |
| 4 | 窗口标题精确匹配 | 真标题是「添加书籍到网站书库 - 豆包工作」，配置里只能写稳定片段「豆包工作」→ 同一个窗口被判成被抢焦点 | 新增 `windowTitleMatch: contains`（默认仍是 exact，不削弱原有守卫） |
| 5 | 第一步是 `activate` 却先做「启动前」焦点校验 | 窗口还没到前台就要求它在前台 → 永远发不出去 | 首步是 `activate` 时跳过「启动前」校验；每步的「后」校验保留 |
| 6 | `kb.ps1` 的 stdout 走控制台代码页（GBK） | Node 按 UTF-8 解码 → 中文标题变乱码 → contains 也匹配不上 | 脚本内 `[Console]::OutputEncoding = UTF8` 钉死输出编码 |
| 7 | 草稿轮询只认 `completion.json` | draft 早就写好了，控制面还要空等到 `maxMinutes`（20 分钟）才收账 | 轮询认 `report.draft.json` 为终态；但 draft 说成功、`output/` 里没有非空文件时继续等，绝不放行 |
| 8 | 虚拟按键没带扫描码（**第 2 次实测才暴露**） | `Ctrl+N` 送出去没人理，而 `Ctrl+V` / 回车正常 → 任务全挤进同一个旧会话 | 按下 / 弹起都用 `MapVirtualKey` 带上真实扫描码（详见 §4） |
| 9 | adapter 的运行参数从未落库（**第 2 次实测才暴露**） | 「这次在不在新会话里跑的」「截图在哪」事后全查不到 | 每次运行落一条审计 `run_params`（`src/engine.js`） |

补的回归测试在 `tests/p6-gui.test.js`（12 条）；全量 `npm test` 从 178 → **190 项全绿**。

## 4. 现场发现：`Ctrl+N` 没有新建会话 —— 已查明根因并修好

**当时的现场**：截图证据 `work-real/_now.png`、`work-real/_after.png`。两次注入都落进了**同一个旧会话**「添加书籍到网站书库」，豆包在该会话里连续处理任务。

**根因（2026-11-15 深夜查明，不是按键时间太短）**：`kb.ps1` 调用 `keybd_event` 时把**扫描码传成了 0**：

```csharp
keybd_event(vk, 0, 0, 0);   // 第三个参数是 flags，第二个是 bScan —— 原来是 0
```

真实键盘按下的每个键都带扫描码。Chromium / Electron 系应用（豆包工作就是）在 `keydown` 里要靠扫描码映射出物理键位（DomCode），扫描码为 0 时会映射失败、被当成无效按键——于是**菜单级快捷键（Ctrl+N）不响应**，而**走输入框的粘贴（Ctrl+V）、回车**反而正常。这正好解释了当时「提示词能贴进去、能发出去，唯独不新建会话」的矛盾现象。

**修法**：按下 / 弹起都用 `MapVirtualKey` 取真实扫描码再发：

```csharp
keybd_event(vk, (byte)MapVirtualKey(vk, 0), 0, 0);   // 按下
keybd_event(vk, (byte)MapVirtualKey(vk, 0), 2, 0);   // 弹起
```

**验证**：在旧会话里按一次 `ctrl+n`，窗口标题立刻从「添加书籍到网站书库 - 豆包工作」变回「豆包工作」，界面回到空白欢迎页（`work-real/_probe-E-ctrln.png`）。

**顺带发现的可用信号**：空白新会话时标题就是产品名本身；一旦进入会话，标题变成「会话名 - 产品名」。这个差异可以当**防错**用（确认切换成功没有），**不能**当完成判据——任务是否完成仍然只认磁盘文件。

### 4.1 于是把它做成了产品能力：`newSession` 步骤

原来的步骤是 `hotkey: ctrl+n`，按了就算完，开没开出来没人管。现在改成显式的 `newSession`：

```yaml
steps:
  - action: activate
  - action: newSession      # 开新会话 + 核对标题，开不出来会重试
  - action: paste
  - action: press
    key: enter
freshTitle: 豆包工作        # 不写就退回用 windowTitle
newSessionAttempts: 2       # 最多开几次
newSessionPolls: 4          # 每次开完轮询几次标题
newSessionPollMs: 400
onNewSessionMismatch: continue   # continue = 照发但标记；blocked = 直接拦下不发
```

三种结果都留痕（写进审计 `run_params`）：

| 情况 | 标记 | 行为 |
|---|---|---|
| 标题变回纯产品名 | `session: "fresh"` | 正常发，新会话里跑 |
| 连开几次还是旧会话标题 | `session: "reused"` | **默认照发**，但报告里能看出串会话了 |
| 同上 + 配了 `blocked` | 状态 `blocked` | **一个字都不贴**，直接拦下（怕污染旧会话时用） |

## 5. 硬边界（必须先知道）

- **会抢键鼠**：整个派活过程（约 20 秒）机器不能同时正常操作；失焦会被检测到并立即中止。
- **会覆盖剪贴板**：提示词走剪贴板粘贴，原来的剪贴板内容留不住。中文只能这么发（`SendKeys` 送中文会乱码）。
- **必须前台**：窗口被别的程序挡住 / 最小化，一律当失败，不会盲按。
- **只认文件**：全程不读屏、不 OCR、不用窗口标题判完成；标题只用来确认「按键有没有打错窗口」。
- **豆包能写文件是前提**：这次它确实能往任意绝对路径写（`D:\...\output\hello.md`）。换别的聊天型助手要先验这一条。

## 6. 怎么复现

```powershell
# 1) 起一个只接豆包的控制面实例（独立库、独立产物目录，不动 3100 演示服务）
$env:AICOMPANY_CONFIG="config/company.doubao.yaml"
$env:AICOMPANY_DB="work-real/aicompany.db"
$env:AICOMPANY_PORT="3101"
node src/server.js

# 2) 发一条任务
curl -X POST http://127.0.0.1:3101/api/requests -H "Content-Type: application/json" --data-binary "@work-real/_demo-request.json"

# 3) 看结果
curl http://127.0.0.1:3101/api/tasks
dir work-real\tasks\<taskId>\output
```

配置要点（`config/company.doubao.yaml`）：`windowTitle` 只写「豆包工作」稳定片段 + `windowTitleMatch: contains`、`reportMode: draft`、`steps` 四步（activate / **newSession** / paste / enter）、`freshTitle: 豆包工作`、`maxMinutes: 20`。
