## 2. 8 份协议（P0-1）

| kind | schema id | 管什么 |
|---|---|---|
| `task` | `aicompany.task/v1` | 任务卡；含 `revision / mode / addressedTo / assignedBy` |
| `progress` | `aicompany.progress/v1` | 进度；**不触发任何事件** |
| `completion` | `aicompany.completion/v1` | 完成报告；`status` 只允许 success / failed / blocked |
| `recurring` | `aicompany.recurring/v1` | 循环模板；`jobVersion / misfire / overlap / 终止条件 / 清理红线` |
| `cycle-summary` | `aicompany.cycle-summary/v1` | 每轮收账；`carryOver / deletedCount` |
| `change-request` | `aicompany.change-request/v1` | 中途刹车；**非终态，每次落盘触发事件** |
| `decision` | `aicompany.decision/v1` | 拍板；四种出口 + `needsHumanApproval` |
| `thread` | `aicompany.thread/v1` | 协作空间；不进任务状态机，只能单向 `promote` |

`revision` / 现场快照复用 `task` 的字段结构，**不另立第 9 份 schema**。

## 3. 三份契约与统一 API（P0-3）

- `AdapterModule`：`type / execute / testEnvironment`，差异全封装在 adapter 内。
- `Channel`（入站）：`start / stop / onInbound`；**禁止**直接写库、直接唤醒 agent、猜测交互模式。
- `Notifier`（出站）：`send / requestApproval`；**禁止** `readInbox()`（v0.4 起读消息归入站）。

端点清单共 **25 条**，代码里是 `src/contracts.js` 的 `API_ENDPOINTS`，测试锁定其中 11 条关键端点：

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/requests` | 提交需求（`requestId` 幂等，可选 `mode/addressedTo/cc`） |
| POST / GET | `/api/tasks` | 建卡 / 看板列表 |
| POST | `/api/tasks/:id/comments` | 过程纠偏 |
| POST | `/api/approvals/:id/decision` | 三道常规门禁 + `replan` 人审 |
| POST | `/api/runs/now` | 人工叫醒 |
| POST | `/api/recurring/:id/pause` `/resume` | 循环启停 |
| GET | `/api/agents` | 候选卡片（席位码 / 能力 / 忙闲 / 配额） |
| POST / GET | `/api/threads` `/api/threads/:id` | 建 / 读协作空间 |
| POST | `/api/threads/:id/messages` `/roll-call` `/promote` `/archive` | 发消息 / 点名 / 单向提升 / 归档 |
| POST / GET | `/api/change-requests` `/api/change-requests/:id` | 上报与读取变更请求 |

| POST | `/api/tasks/:id/cancel` | 取消收尾 |

| GET | `/api/inbox` `/dashboard` `/runs` `/audit` | 待办 / 状态 / transcript / 审计 |

**Web Board 最小页（§18 D5）**：`Tasks / Approvals / Inbox` 三页 + 模式下拉与「交付给」选择器 + 最小 Threads 消息流；`Dashboard / Runs / RecurringJobs / Threads 完整页 / ChangeRequests` 放 P4。

## 5. 怎么跑（零安装）

```bash
cd D:\开源\AICompany
npm test                                    # 44 个用例，无需 npm install
npm run schemas                             # 列出 8 份 schema
AICOMPANY_CEO_CMD=echo AICOMPANY_WORKER_CMD=echo npm run doctor
                                            # 5 项体检全 OK
node src/cli.js validate task <某个 task.json>
```

`company.example.yaml` 里的命令写成 `${AICOMPANY_CEO_CMD}` / `${AICOMPANY_WORKER_CMD}`。**不设这两个环境变量时 `doctor` 会明确报 `ENV_MISSING` 并退出，且全程只读、不创建任何文件**——这正是清单 P0-2 的验收项。

## 7. 与任务书的四处偏差 / 待办（如实记录，不藏着）

1. **语言与构建链**：§10.1 定的是 **Node.js + TypeScript**。P0 用的是**纯 ESM JavaScript**（零构建步骤，Node 22 直接 `npm test`）。理由：P0 只有协议、校验与测试，没有状态机那种需要类型护航的复杂逻辑，先不引构建链能让你打开就能验收；**P1 引入 TypeScript 与 `tsc` 时再整体切换**，8 份 schema 是 JSON、`validate()` 接口不变，切换不影响其它模块。若你要求现在就上 TS，我改。
2. **配置校验库与依赖**：§18 D8 的倾向是「YAML + zod」，§10.5 列了 `typescript / js-yaml / zod / better-sqlite3 /...`。P0 为了做到**零外部依赖**，改用了自研的 JSON Schema draft-07 常用子集校验器 + 受限 YAML 解析器。§10.5 本来就把依赖写成「拟，P0 时确认版本」，此处即 P0 的确认结果：**核心依赖为零；`js-yaml` / `zod` 延后到 P1，`better-sqlite3` 到 P1 建表时才装**；`validate()` 与 `loadConfig()` 接口不变。
3. **§6B.11 的 CI grep 示例会误报**：`grep -rniE 'dsh|doubao|...'` 里的 `dsh` 会命中 `needsHumanApproval`（含 `dsH`）。P0 测试已改用**词边界** `\b(dsh|...)\b`；建议任务书后续把这两条 CI 命令同步改成带 `\b` 的写法。
4. **文档引用错位（已修正）**：v1.0 全文复核时新增 R14–R16 后，§6C.5 的「TTL / 归档」仍引用 §16 R14，而 R14 现在指「汇报了但系统没接住」，材料堆积对应 R15。本轮已把该处引用改为 R15（错字级修正，不动设计）。

> 第 1、2 条是**技术选型层面的可回退决定**，不影响协议、字段、验收判据；第 3 条是任务书文档本身的错漏；第 4 条已就地修正。
