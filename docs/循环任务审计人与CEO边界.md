# 循环任务的审计人 & CEO 的边界

> 2026-11-16 22:30–23:00　董事会定：
> 「循环任务里，日常工作以后你来审计就没必要给 CEO 了……CEO 只负责宏观任务规划、方向性的设计，
> 只有这些东西动了，才需要 CEO 审计，其他常规任务 CEO 安排给下面的人审计就好了。」
> 「CEO 不会自己去处理工程任务的拆分……真公司里 CEO 只负责定方向，不要老让 CEO 管小事儿。」

---

## 一、结论先说（三句）

1. **日常循环活（巡检 / 体检 / 清理 / 简报）→ 工程执行审**，不再每周烧一次总经理。
2. **现有 2 条排班已经改完**（版本 v1 → v2，改库前有备份，审计留痕），下周一 / 下月 1 号起就按新规则走。
3. **CEO 只定方向和结果**：提示词、岗位职责、边界三处都写死了「不替工程岗拆实现」，它再拆到文件/命令一级就是越界。

---

## 二、循环任务由谁审（新规则）

| 任务性质 | 谁审 | 怎么定 |
|---|---|---|
| 日常 / 定期活：巡检、体检、清理、例行维护、常规简报 | **工程执行（engineering）** | 系统默认。CEO 建议里不写 `reviewBy` 也落到这里 |
| 方向性长期任务：会改项目走向、对外承诺、技术路线 | **总经理**（`reviewBy: "ceo"`） | CEO 必须在建议里显式写明，并在 `reviewNote` 说清「为什么这个必须我看」 |
| 董事会要亲自看 | **董事会**（`reviewBy: "human"`） | 每轮出一张「待你拍板」单，通过才收账 |

配套三条硬约束：

- **不能自己审自己**：`reviewBy` 写成执行人本人（比如循环派给谁就写谁）→ **整条建议被拒**，不会送到董事会面前。
- **写死了就绕不过去**：卡上带 `reviewBy` 就等于「必须审」；执行人交活时自报 `handoff: land` 会被拦下并留痕
  （`handoff_downgraded`）。以前发布者是「政策」时它会一路落盘，现在这个口子堵上了。
- **配置可换人**：`config/company.prod.yaml` 的 `artifacts.routineReviewer: engineering`；
  没配就退到 `defaultReviewer`，再退到「第一个带 review 能力的席位」，都没有就交董事会亲审 —— **绝不默认回 CEO**。

## 四、必须知道的一个副作用（以及防线）

工程岗是**拉模式**席位：人叫才醒，不是常驻进程。所以每一轮做完，卡会停在 `in_review` **等我去审**。

- 没人审 → 这一轮不收账 → 下一轮到点时按 `overlapPolicy: skip` **跳过一轮**。
- 为了防止「它看着在跑、其实早停了」，卡排队等审时**董事会消息区会收到一句提醒**：
  「第 N 轮做完了，按排班交给工程执行审；它审完这一轮才收账，一直没人审的话，下一轮到点会按『上一轮还没完』跳过。」
- 我这边领审：`npm run seat -- reviews`（列出待审）→ 看结果 → `npm run seat -- verdict <taskId> pass|reject --reason "…"`。
- 以后如果想更省心，可以加「超过 N 天没人审就自动降级给董事会」这类兜底；现在先按「提醒 + 人叫醒我」走，不擅自改变审的语义。

## 五、CEO 不做工程拆解（这次落到了哪里）

| 层 | 改了什么 |
|---|---|
| 提示词（`src/org-chart.js` → `ceoRoutingBriefing`） | 开头新增「你的位置：定方向，不下场」：**只需回答四件事——这是什么任务、是不是新项目、需求是什么、要什么结果**；具体怎么拆实现、先改哪个文件、跑什么命令、用什么库是工程岗的活；除非董事会要方案，否则不写实现步骤 / 不写代码 / 不定技术选型 |
| 拆卡粒度 | 从「一张卡一个交付物，最多 8 张」改成「**默认给工程岗一张『做成什么样』的卡，由它自己拆实现**；只有跨工种或确有前后依赖才拆两三张」；明写「不要为了拆得细把一件事切成五步流水账」 |
| CEO 输出契约（`src/adapter-webhook-exec.js`） | 「怎么拆」整段重写：你是总经理不是工程组长；不写实现步骤、不指定技术选型、不写代码 |
| 岗位定义（`config/company.prod.yaml`） | `duties`：定方向与结果标准、判断归属与新项目、派给能独立交付的席位、审方向性结果、对董事会负责；不自己拆实现。`boundaries` 增加「不替工程岗拆实现步骤 / 不指定技术选型」 |
| 机制（早就有，这次确认仍然生效） | ① 严禁自干的三道闸：CEO 点自己当承接人会被改派执行席位；② 子派活只能派进自己的汇报子树，不能越级；③ 工程岗接到卡后可以自己拆（`spawnChild`）、也可以把卡打回要求改需求 —— 拆解权在它手上，不在 CEO 手上 |

一句话：**CEO 管「做什么、做成什么样、归谁」，工程岗管「怎么做」。**
