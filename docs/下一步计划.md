## 1. 会话怎么隔离 —— 已解决（2026-11-15 23:45）

**原判断有误，已查明真实原因**：`Ctrl+N` 不是「弹了别的面板」，也不是按键时间太短，而是 `kb.ps1` 发虚拟按键时把**扫描码传成了 0**。Chromium / Electron 系应用要靠扫描码映射物理键位，扫描码为 0 就当没按——所以菜单级快捷键（Ctrl+N）不响应，而走输入框的粘贴、回车反而正常。

**修完的结果**：`ctrl+n` 立刻开出空白新会话（标题从「会话名 - 豆包工作」变回「豆包工作」），真机复验 `session: fresh`。

**产品化后的形态**（不用再选方案了）：

| 情况 | 标记 | 行为 |
|---|---|---|
| 标题变回纯产品名 | `session: "fresh"` | 正常发，新会话里跑 |
| 连开几次还在旧会话 | `session: "reused"` | 默认照发，报告里能看出串会话了 |
| 同上 + 配 `onNewSessionMismatch: blocked` | 状态 `blocked` | 一个字都不贴，直接拦下 |

**边界说明**：读窗口标题只用于「确认切换成功没有」（防错），**不用于判断任务是否完成**——判完成只认磁盘文件，不违反 §8.3。

坐标点击能力仍留在 `kb.ps1`（`-Action click`，支持绝对坐标与相对窗口坐标），留给以后遇到没快捷键的应用；这次用不上。

### 2.2 后做 G2 —— 完成即触发下一轮（要设计）

现在是 scheduler 按 rrule **到点**触发；验收要的是「这张卡一完成，下一轮立刻开始」。

做法：Run 终态 `success` 时，查这张卡所属的 `RecurringJob` 是否配了 `trigger: onCompletion`，是就直接派生下一轮。

**必须同时做的防呆**（不做会烧配额、会自激）：

| 防呆 | 为什么 |
|---|---|
| 连续失败 N 次自动停手 + 写审计 | 否则「失败 → 立刻重试 → 再失败」会无限烧配额 |
| 两轮派生之间加最小间隔（如 30 秒） | 防止瞬时连爆把队列打满 |
| 同一个 Job 同时只允许一轮在跑 | 防止叠跑同一件事 |

**验收**：一张卡完成后 1 秒内出现下一轮；把任务故意做成必失败，跑到 N 次后停住且审计里查得到。

## 5. 服务器部署：现在不需要，什么时候才需要

单机现在够用。出现下面任意一条才值得上：

- 你想在手机 / 外面下单（看板得能被外网访问）；
