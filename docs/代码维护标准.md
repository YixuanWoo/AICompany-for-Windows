# AICompany 代码维护标准

版本：v1（2026-11-23 定）。适用范围：`src/`、`scripts/`、`tests/`、`config/`、`docs/`。
这份是**给人和 agent 一起看的硬规矩**：改代码前先对一遍，改完按 §9 的检查清单跑一遍。

## 1. 依赖与运行时

- `src/` 引擎**零运行时依赖**，`package.json` 的 `dependencies` 与 `devDependencies` 必须都是 `{}`（`tests/p2.test.js` 守着，缺一个就 `undefined !== {}`）。
- 需要原生能力的（如 `node-pty`）只能进 `scripts/`，且必须 `try { await import(...) } catch { … }` 可选加载、缺包时给出人话报错，**不写进 package.json**。
- Node ≥ 22（用到 `node:sqlite`、`node:test`）。

## 2. 协议与冻结面

- `aicompany.completion/v1`、状态枚举、`events`/`change_requests` 等表结构属于冻结契约，**不为方便而加字段、加枚举、加列**。
- 确实要扩，走「加列不加枚举」或「可选字段 + 向后兼容」，并在文档里写明哪一条契约被碰了、为什么。
- 所有 adapter 出口的 JSON 形态只有两种：裸业务对象，或 `{status, usage, result, sessionParams}` 信封。`src/adapters.js` 的 `normalize()` 统一拆包，**不要在别的环节再发明第三种形态**。

## 3. 证据纪律（最容易被改坏的一条）

- **产物只信控制面自己核对出来的**，不采信 agent 自报。`src/gui-report.js` 的三条纪律不许放水：
  1. artifacts 由扫描 `output/` 得出；
  2. draft 说 failed / blocked 就按失败走，不补全成 success；
  3. `output/` 没有非空文件就不算成功。
- **进度与完成是两套判定**：`ack.md` / `progress.json` / `run-progress.json` / `run-heartbeat.json` / output 增长 = 进度；`report.draft.json` + `completion.json` = 完成；`blocked.json` / `change-requests/` = 停手。**不许用「目录里有没有文件」去否决席位自己交的完成信号，也不许把「有进度」判成「失败」。**
- 上一轮草稿不能当本轮成果：`readDraft` 必须带本轮 `runStartedAt` 的 mtime 下限。

## 4. 落盘边界

- **产物落点（2026-11-23 起生效）**：项目产物直接写 `ctx.project.writeDir`（引擎按项目配置算好的
  绝对路径），**禁止写 `output/`**；`output/` 只放任务卡、说明、进度、完成报告等 AICompany 自己的文件。
- 完成报告用 `deliverables`（绝对路径清单）声明真实产物；控制面逐条核验存在/非空/落点内，
  checksum 一律控制面自算，不采信席位自报的 hash。
- 产物已在项目目录时，交付只记账（`mode: 'in-place'`），**不再复制副本**；只有旧的 `output/...`
  相对路径产物才走复制交付。
- 公司目录（`workRoot`）只放：任务卡台账、项目规范与经验记忆、产物清单与校验和、过程证据、临时工作区。
- 项目目录是**资产**，不是公司的中转仓。交付走 `deliverTask`：
  - 落点必须解析在 `rootDir` 之内，`deliverSubdir` 只能是相对子目录；
  - 只新建、不覆盖、不删除（同名加任务号后缀）；
  - **交付前必须过 `deliverableOf` 过滤**：控制面文件、脚本/可执行文件、校验/调试输出不进项目，被挡的写进 `skipped`，不静默丢；
  - 落盘失败不改卡状态，只写审计与台账，等心跳重试。
- 新增「往公司外写文件」的能力，必须先回答：落点谁授权、越界怎么拦、失败了谁看得见。

## 5. 安全红线

- 带 `--dangerously-bypass-approvals-and-sandbox` 这类提权参数的席位，**必须同时有越界守卫**（现在是 `scripts/cli/doubao-cli-bridge.mjs` 的 `GUARDED_DIRS` 指纹比对 + 掐断 + `out-of-scope.json`）。提权而不看守 = 不允许合入。
- 窗口标题、快捷键、按键一律来自配置，源码里不写死任何一个（`gui-prompt.js` / `normalizeSteps`）。
- 清理类扫描只出报告不删除，且必须过 `cleanup.js` 的白名单 + 敏感目录拒绝。
- 提示词是**不受信输入的组装处**：对象进提示词前必须显式取文本字段（教训：`String(ctx.project)` 拼出 `[object Object]`，CLI 席位长期拿不到项目规范）。

## 6. 错误与日志

- 业务失败 ≠ 进程失败：桥接/适配器**永远 exit 0**，状态放在 JSON 里，否则引擎会把「没干成」当「适配器挂了」。
- 失败要能被看见：写审计（`writeAudit`）或写台账，**不允许关键路径上空 `catch {}` 吞掉唯一线索**；可读性优先于省事，错误文案要带「哪一步、哪个文件、什么码」。
- 日志用 `src/logger.js`（按天轮转、只追加、不自动删）。

## 7. 测试

- 框架 `node:test`，零依赖；临时目录用 `fs.mkdtempSync` + `t.after(() => fs.rmSync(...))`。
- 改契约、改判定、改落盘，**必须同时带回归测试**，测试名写清守的是哪条规矩、源自哪次事故。
- 顶层就执行 `main()` 的脚本（如 CLI 桥接）不能 import，用**源码断言**守关键行为（参照 `tests/cli-bridge-prompt.test.js`、`tests/board-evidence.test.js`）；能抽成纯函数的就抽出来写真单测，不要长期停留在源码断言。
- 测试里不许连生产库、不许碰真实项目目录、不许起 GUI。

## 8. 文档

- 每轮维护留一篇记录：**改了什么、为什么、证据（命令 + 数字）、没做什么、下一步**。放在 `docs/`，文件名带日期。
- `docs/P*` 系列文档的标题要反映真实状态（未开工 / 已实施 / 已上线），实施了还写「未开工」就是误导。
- 方案类文档必须写「重启条件」：什么情况下这个暂缓项该被翻出来做。

## 9. 提交前检查清单

```powershell
# 1) 语法（全量，含 scripts）
Get-ChildItem . -Recurse -File -Include *.js,*.mjs |
  Where-Object { $_.FullName -notmatch 'node_modules' } |
  ForEach-Object { node --check $_.FullName }

# 2) 全量测试
node --test

# 3) 生产配置自检
npm run doctor:prod

# 4) 硬编码本机路径（开源前必须清零，生产 config 除外）
#    重点：D:\npm-global、DoubaoWork.exe、D:/Demo、D:/开源
# 5) 提示词拼接：对象直接 String() 进文案的地方
# 6) package.json 的 dependencies / devDependencies 仍为 {}
```

通过标准：语法全过、`node --test` 全绿、doctor 全绿、没有新增硬编码、没有新增「提权但无守卫」的席位。
