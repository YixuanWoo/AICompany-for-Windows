# 董事会消息箱：所有汇报改成「一句人话」

日期：2026-11-16　｜　改动：`src/messages.js`（新增）、`board_messages` 表、`/api/messages`

## 一、原来哪里不对

以前同事干完活，董事会看到的是两样东西，都不好用：

| 原来给的 | 问题 |
|---|---|
| **简报**（BRIEF-27：今日完成 27 / 进行中 0 / 累计唤醒 42 次） | 这是**统计**，不是「谁干了什么」。看得懂数字，看不出结果 |
| **汇报文档**（report.draft.json、completion.json、某个 .md） | 要人一篇篇点开读；机器文件名对人没有意义 |

董事会要的其实只有一句：**谁、干了什么、结果如何、我要不要动手。**

## 二、现在的做法：消息箱

新增一张表 `board_messages`，四个栏位最要紧：`fromAgent`（谁说的）、`kind`（哪类话）、`title`、`body`（人话正文）。

界面「任务与汇报」页第一个卡片就是**消息区**，所有同事说的话都在这一个列表里，按时间倒序。

### 一条消息长这样

```
完成：整理第 3 份文档的词条表
豆包（执行） · 11-16 21:40 · demo
─────────────────────────────
豆包（执行） 干完了：整理第 3 份文档的词条表
它说：词条表理好了，42 条，按原文出现顺序排的。
东西是这些：词条对照表.md。
已经放进「文档处理项目」 的 04-out 文件夹（1 个文件）。
你不用管，这件事已经办完。
                     [看这张卡 →]
```

五句话对应五个问题：**谁先说 / 干了什么 / 结果是什么 / 东西在哪 / 要不要你动手**。

## 三、四类消息

| kind | 什么时候出现 | 人要不要动手 |
|---|---|---|
| `done` | 卡办完了（机器验收 / 直接落盘 / 上级审过 / 你点通过） | 不用 |
| `blocked` | 卡住了、上报了（含「受管代码没登记仓库」这类打回两次） | 要，得给方向 |
| `decision` | 中途做不下去，要你定一件事，卡已挂起 | 要，定完它接着干 |
| `answer` | 总经理只回话、没派活（问一句答一句） | 看情况 |

同一次「干完」只发一条。**只派活不干活的父卡不发**（成果已经由每张子卡各报一次）；系统自己建的「处理升级」卡也不发（它本来就是一条消息）。

## 四、怎么保证说的是人话

三处使力，缺一不可：

1. **让干活的人自己写**：完成报告里新增 `boardNote` 字段，提示词明确要求「一句结论，不写路径、不写字段名、不写请查看报告」。有它就用它，没有才退回 `summary`。
2. **引擎兜底清洗**：`plainText()` 去掉 markdown 记号、代码块、整段 JSON；标题只有两个字（比如「报告」）就接上第二段；超过 200 字截断。
3. **内部文件名不进消息**：`completion.json` / `report.draft.json` / `progress.json` / `cycle.json` 一律过滤，产物只显示文件名（`terms.md`），不显示 `output/xxx` 相对路径。

## 五、界面怎么用

- **未读**：左边一条橙色亮边 + 标题前「未读」标签，卡片标题旁显示「N 条未读」；
- **已读**：点消息任意位置即标已读；
- **只看未读**：按钮切成只看未读，再点回看全部；
- **全部标记已读**：一次清零；
- **看这张卡 →**：跳过消息，直接开那张卡的完整结果（汇报 + 产物 + 验收条件）。

原来的「简报」没删，挪到「观测与运维」页，改名「系统简报」，查账用。

## 六、接口

```
GET  /api/messages?limit=60&unread=1     → { messages: [...], unread: N }
POST /api/messages/read  {"all": true}   → { marked: N }
POST /api/messages/read  {"ids": ["MSG-..."]}
```

命令行交活时可以带一句人话（不写就退回 summary）：

```bash
node scripts/seat.js --as engineering report \
  --summary "写了 board-msg-check.md，讲清消息区怎么用" \
  --note "消息区说明写好了，两段话，打开就能看懂。" \
  --kind document
```

## 七、顺手修的真 bug

原来 **CEO 验收通过**的卡只改状态，不落盘、不写项目记忆：

```js
if (outcome.result.verdict === 'pass') {
  transition(db, task.taskId, 'done', 'ceo', outcome.runId);   // 就这一句，没有然后了
}
```

后果是：看板显示「完成」，产物却一直躺在 `work-prod/tasks/<id>/output/`，项目文件夹里空空如也，经验也没入库。
直投落盘、审批通过、席位审查三条路都落了，只有 CEO 这条路漏了。已补齐（同一口径：先落记忆再落盘），消息也因此才补得上「放进哪个文件夹」。
