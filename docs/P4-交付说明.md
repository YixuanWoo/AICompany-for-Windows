一句话：**P3 让"能干活的 AI 公司"跑起来了；P4 让它"像个公司"——管人（配额 / 汇报线）、管钱（额度）、该人拍板的地方真停下来等人、出问题能查账。**

日期：2026-11-15｜清单进度：36/54 → **46/54**｜全量测试 **156/156**｜真实 HTTP 冒烟 9 组全过

## 一、这一步到底在解决什么问题

P1–P3 跑通的是「一条需求 → 自动干完 → 出报告」。但真实公司不是这样的：

| 现实里的麻烦 | P1–P3 的状态 | P4 补了什么 |
|---|---|---|
| 某个席位一天被叫 200 次，烧钱烧到失控 | 只有 `quotas.used` 记账，没人拦 | 到 80% 预警、到 100% **停派新活**，还能人工清零 |
| CEO 想拆活，但方向错了不能直接开干 | 直接派活 | **战略门禁**：人点头才派；可以要求重写、可以驳回 |
| 活儿老不合格 | 自动重试 2 次就 blocked 卡住 | 出**人审卡**：通过=返工 / 重写=换人 / 驳回=放弃 |
| 干到一半发现前提变了 | 只能派新卡，原来干的一半丢了 | **挂起**（保住现场 + 半成品）→ 人拍板 → 四种出口之一 |
| 出了事查不到"谁在什么时候做了什么" | 有 audit 但有表没页面 | **Activity 时间线**：一张卡从生到死按时间串起来 |
| 让 AI 顺手清理磁盘 | 不敢做，怕删错 | **只扫描出报告**，`deletedCount` 恒 0，Desktop / AppData 直接拒绝 |

这就是 P4 的全部动机：**把"自由发挥"换成"有边界、有人管、可追溯"。**

## 二、四组能力，人话版

### 1）管人管钱：配额（P4-1）

给每个席位一个「本周期能用多少次」的账本。规则三条：

- 用到 **80%** → 出一次预警（一个周期只报一次，不刷屏）
- 用到 **100%** → **停止派新活**并通知（不是"警告一下继续干"，是真停）
- 跨周期（默认 24h）→ 自动开新账；人工也能一键清零

这里有个坑我踩了：原来只在**派活前**检查，意味着「刚好用到 80%」要等下一次派活才报——如果这个席位当天不再派活，**等于没预警**。改成**记完账立刻判一次**，账本一动就联动通知。

### 2）该人拍板的地方真停下来（P4-2 / P4-8）

五类人审，全部在看板一键处理：

| 类型 | 什么时候出现 | 你能做什么 |
|---|---|---|
| `strategy` 战略门禁 | CEO 拆完活想派出去 | 通过（派活）/ 要求重写（打回 CEO 返工）/ 驳回（原卡取消） |
| `review_reject` 验收打回 | 连续不合格 | 通过（返工）/ 重写（**换人**：优先救火席位）/ 驳回（放弃） |
| `hiring_budget` 招人预算 | 要加席位 | 只记结论，系统不动任务（钱的事人说了算） |
| `replan` 改方案 | 决策者想改指令 / 验收条件 | **必须**人点头，才算数 |
| `recurring_change` 循环改版 | 想改循环任务的频率 / 模板 | 点头后 `jobVersion+1`，**只影响新轮次** |

### 3）能查账（P4-4）

看板加了「运行与审计 · Activity」：选一张卡，把它经历的全部东西按时间列出来——
状态怎么变的、被谁唤醒过几次（`runId`）、报过几次变更、拍过什么板、走了哪些审批、**按第几版指令跑的**（`revision`）、现场快照长什么样。

### 4）两条"完整档" + 循环 L3（P4-7 / P4-8 / P4-9）

- **§6C 完整档（协作空间）**：开会三档 `readonly`（公告，零唤醒）/ `rollCall`（最多点 2 位）/ `full`（全员 + CEO 汇总，**要两道确认**）；`autoAssign` 默认只推荐不替人选；`promote` 单向提升成任务卡，提过一次就不能再提；空间放太久（TTL）自动归档，归档后拒收消息。
- **§6D 完整档（刹车）**：干到一半撞墙 → 任务进 `awaiting_decision`（**不烧额度、不被补偿扫描重跑**）→ 现场快照落盘（只读、不可改）→ 人从**四种出口**里选一个：

| 出口 | 含义 | 关键约束 |
|---|---|---|
| `resume` 续做 | 接着原来的活干 | **沿用原 `runId`**，`output/` 里的半成品还在 |
| `redo` 重做 | 推翻重来 | 换新 `runId`，`attempt+1` |
| `derive` 另起 | 目标变了，另起一件 | 新卡 + 原卡 `cancelled`；跨子树派活会被拒 |
| `cancel` 取消 | 不做了 | 终态，快照和产物保留可查 |

  挂起太久怎么办？**24h 提醒一次、72h 自动取消，绝不自动恢复**（悄悄接着干是最危险的）。
- **循环 L3 + 清理红线**：循环任务改版必须人审；清理类任务强制 `requiresHumanEachCycle: true`，扫描路径只要命中 Desktop / Downloads / Documents / AppData / Library / 系统盘 / `.ssh` / `.config` → **整体拒绝且一个文件都不写**，报告里 `deletedCount` 恒为 0。

## 四、修掉的坑（都是真踩出来的）

| # | 现象 | 根因 | 怎么修的 |
|---|---|---|---|
| 1 | 用了 80% 却没人知道 | 阈值只在派活前判，账本变了下一次才检查 | 记账后立刻判一次（`afterQuotaConsume`），共用去重位 |
| 2 | 决策者 `w1` 的上级是 `lead`，却解析成 `ceo` | `resolveDecisionMaker` 从**自己**开始找，把"自己的上级"多跳了一级 | 改为从 `reportsTo` 开始找，第一个有 review/plan/delegate 的上级 |
| 3 | `promote` 后卡一直 `todo` | 建卡只发事件，没人推进事件泵 | `promoteThread` 改 async，内部 `pump()`；接口同步 `await` |
| 4 | 归档报 `no such column: archivedAt` | `threads` 表没这列 | DDL + 迁移补列 |
| 5 | 循环任务改版报「不允许的多余字段」 | 把运行时状态（`lastFiredAt` 等）一起塞进 schema 校验 | 校验前只取协议字段；补丁含未知字段则**明确报错**（不静默丢弃） |
| 6 | `full` 档错误信息看不出要"二次确认" | 文案说得含糊 | 统一成「full 需要二次确认：…确认请传 confirm: true」 |
| 7 | 决策被拒却在 `decisions` 留了一条"已拍板" | 先写记录后校验（跨子树检查在 `buildCard` 里） | 校验前移：先验能不能派，再落记录 |
| 8 | 改了验收条件，人审通过后重提**又生成一张审批**，永远走不到执行 | 重提时没有"已过审"的凭据 | 批准时给决策**盖 `approvalId` 章**，重提凭章直通 |
| 9 | adapter 的 `status` 元字段让变更请求整单被拒 | 引擎把 adapter 返回值原样当业务单据 | 按协议字段白名单取（`pickSchemaFields`） |
| 10 | HTTP 调决策接口必报 `$.taskId 缺少必填字段` | 客户端只有 URL 上的 `changeRequestId` | 服务端从变更请求反查补 `taskId`；给了就必须对得上 |
| 11 | `submitDecision` 传 `assert.throws` 抓不到错 | 它是 async | 测试改 `assert.rejects`（实现没错，测试写错） |

> 第 9、10 条是**冒烟才发现的**——单元测试里 `taskId` 一直是我自己传的，`status` 也没人带，所以没暴露。这就是为什么每阶段都要真起服务打一遍。

## 六、边界与如实交代（没做到 / 做偏的）

| 项 | 状态 | 说明 |
|---|---|---|
| G3「≥3 岗位按**难度**分流」 | **仍留空** | P4-3 已落地按能力 + 配额排序、跨子树校验、汇报线解析决策者；但任务卡上没有**难度等级**，也没有难度→席位的映射规则。硬编一个等于骗人，留给 P5 用真实任务校准 |
| G2「任务**完成后**立即触发下一轮」 | **仍留空** | 循环任务目前是**定时驱动**（rrule 到点），不是完成驱动。P4 没动这块 |
| `replan` 的「改动前后对照页」 | **只做了数据 + 列表** | Activity 里能同时看到 `before` / `after` 的 acceptance 与 instructions（审批卡 payload 带全），但没有专门的左右对照 UI。看板这一版以"能看懂、能操作"为准 |
| 会议 `full` 的「二道确认」 | **做在开会 + 点名两处** | 浏览器里用原生 `confirm()` 兑现，没有做成自定义弹窗。功能到位，样式朴素 |
| 清理扫描的「真要删」 | **故意不做** | 红线就是"绝不自动删"。真要删必须另起一次性任务逐项人工确认，本阶段不碰 |
| 挂起态「跨进程恢复」 | **依赖 `/api/change-requests/expire` 被调度** | 引擎提供了扫描函数和端点，但没有内置后台定时器常驻。真实部署时挂到 scheduler tick 里（P5 试运行阶段接） |
| 看板 Activity 的规模 | **只列最近若干条** | 一条卡几万条审计时前端会卡；现在截取尾部 N 条，没做虚拟滚动 / 服务端分页 |

## 七、对你（用户）的实际影响

- **想让它别乱烧钱** → 看板「配额 · Quotas」进度条 + 一键重置；触顶的席位会直接在统计条上计数。
- **想让它别自己瞎决定** → `company.yaml` 打开 `gates.strategy: true`，CEO 每次拆活都要你点头。
- **想改主意又不想它白干** → 挂起区点「续做」，原来的半成品和 `runId` 都留着。
- **想查它到底干了啥** → Activity 选卡，从建卡到 done 一行一行看，连"按第几版指令跑的"都有。
- **想让它清磁盘** → 清理扫描只给你清单，一个文件都不删；Desktop 这类目录它会直接拒绝并说明原因。
