# 岗位守界改进方案（合并两轮讨论）

> 依据：2026-11-17 两轮只读检查（GUI 席位身份断口、CEO 施工图式派活、无「先判断」前置、
> 无自做/派下的尺子、CEO 看不到他人边界、`adapter?.type` 误判）。
> 原则：**只改提示词与配置，不加拦截闸**。目标是「绝大多数时候守流程，允许小活弹性自做」。

## 目标（怎么算改好了）

1. 任何席位（不论哪种 adapter）开工前都先看到同一段【第 0 步：先判断，再安排】。
2. 工程岗身份明确写成技术负责人（CTO），默认不写实现；**单点小改允许自做但必须留痕**。
3. CEO 知道全公司每个岗位是谁、干什么、不许干什么、归谁管；它派的卡必须带**授权话术**。
4. 席位「顶回去」有正当通道（change-request / escalate），不再只能用 failed 表达。
5. 全量测试通过、`doctor:prod` 通过、常驻实例重启并确认加载新码。

1. **弹性是否真被用起来，只能看真机数据**：本文只保证提示词讲清了「小活可自做、大活必须派」，
   下一轮要复查 `tasks` 里 engineering 的子卡比例、以及报告里有没有「这个我自己改了，因为…」的留痕。
2. **change-request 仍是 0 条**：通道和话术都有了，但要等第一次真的出现「上级方案不成立」才会用到。
   若下轮仍为 0，说明不是通道问题，而是「顶回去」的动机还没被讲够（需要看具体卡再定）。
