# 席位模型整改：岗位是岗位，人是人

2026-11-16 · 董事会质询后整改

## 一、这步到底是咋回事

之前配置里一个 `agents` 数组，把两件事混在一起写：

- **岗位**：公司里需要的角色，总经理、执行工。
- **担任者**：真正干活的那个东西——豆包工作（桌面应用）、8080 上的 agent。

混着写之后，就出现了你看到的现象：`豆包工作` 被当成了"席位名"，`CEO` 被当成了"某个 agent 的名字"，还有我上一轮擅自加的 `研发工位(真agent)`——那是第四个人，既不是岗位也不是你有的 agent。

**结论先给：CEO 不是 agent，是岗位名。** 你需要的岗位只有两个：定方向的人（总经理）、干活的人（执行）。担任这两个岗位的，只有你手里实际有的东西。

## 二、为什么要改

1. 名字乱：同一行配置里既有岗位名又有人名，看板显示出来分不清"这是位子还是坐在位子上的人"。
2. 多出一个不该有的席位：`研发工位`（内部 id `ceo-agent`）是我为了让 CEO 有活可派硬造的，你没批准过，而且它走 8080，烧的是你最贵的额度。
3. CEO 可能自己干：引擎里按难度分派，只看"接不接得住"，没看"这个位子是不是总经理"——它在输出里点自己的名字，就会被派给自己。

## 三、怎么改（三件事）

| 改什么 | 怎么改 |
|---|---|
| 名字 | 每个席位多两个字段：`post`（岗位）和 `holder`（由谁担任）。看板分两行显示：岗位一行、担任者一行。`id` 只作内部标识，不再当名字用。 |
| 席位数量 | 删掉 `研发工位(ceo-agent)`。只剩两个岗位：总经理、执行。执行岗由豆包工作担任。 |
| 禁止自干 | 三道闸：提示词写死红线；输出必须是拆卡/验收契约；引擎派卡时强制排除总经理岗——它点自己也会被改派给执行岗。 |

## 四、具体改了什么

**配置** `config/company.prod.yaml`
```yaml
- id: ceo
  post: 总经理
  holder: dsh 规划 agent      # 担任者：8080 上那个 agent
  holderKind: external-agent
- id: doubao
  post: 执行
  holder: 豆包工作            # 担任者：桌面应用
  holderKind: gui-app
```
`ceo-agent` 整段删除。

**引擎**
- `src/config.js`：解析并派生岗位/担任者；新增体检项「每个席位都写明岗位与担任者」。
- `src/core.js`：名册新增 `postTitle / holderName / holderKind` 三列（老库自动补列），启动时按配置同步——配置里删掉的席位会从库里清掉。
- `src/engine.js`：派卡函数加硬闸 `seat.isCEO !== true`，总经理岗永不接执行卡；名册注入改成「岗位 → 担任者」。
- `src/adapter-webhook-exec.js`：CEO 提示词加红线段，写明「唯一允许做的事就是输出那个 JSON，自己动手这轮直接作废」。
- `src/web/board.html`：席位卡片改成两行；界面里 30 处 "CEO" 统一改成"总经理"。

**测试**：新增 P7-10——CEO 把卡派给自己时，必须被改派给执行席位。全量 **280/280 通过**。

## 五、修复结果

重启 3100 后实际名册：

| 席位 id | 岗位 | 担任者 | 类型 |
|---|---|---|---|
| ceo | 总经理 | dsh 规划 agent | 外部 agent |
| doubao | 执行 | 豆包工作 | 桌面应用 |

`研发工位` 已从库里清掉（不是隐藏，是删除）。生产配置体检 7 项全过。

## 六、两条实话

1. **dsh 里没有叫 CEO 的 agent。** 8080 上跑的是一个 agent 运行时，被两个通道驱动（飞书秘书、本引擎的 webhook）。「总经理」只是这个引擎给它派的岗位名，担任者一栏写的"dsh 规划 agent"就是它。
2. **执行岗换成豆包工作后，有代价**：它抢键鼠、一次只干一件、需要屏幕不锁且你不碰电脑；改代码这类活它做不精确。总经理在拆活时能看到这个限制，但最终能不能干成，取决于活的性质。如果某类活长期做不好，再考虑给它配第二个执行岗——那是新增岗位，需要你点头，我不会自己加。

## 七、额度

总经理岗 `quotaDaily: 40`（一天最多 40 次唤醒），执行岗 20。本轮整改**没有向 8080 发任何任务**，只重启了 3100 加载配置，零 token 消耗。
