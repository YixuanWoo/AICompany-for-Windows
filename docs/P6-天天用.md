| 代价 | 收法 | 开关在哪 | 真机证据 |
|---|---|---|---|
| **抢键鼠** | ① 同一时刻只有一张 GUI 卡在跑（全局互斥锁）②「静置 3 秒才动手」，你正在打字它就不抢 ③ 想彻底停手就点暂停 | `gate.requireIdleSec` / 看板暂停按钮 | 审计 16:21:01 `user-active`：「你 **0 秒**前还在操作键鼠（要求静置 3 秒），先让你用，稍后自动重排」——卡退回 `todo`，**不扣额度、不算失败** |
| **剪贴板被覆盖** | 发提示词前把剪贴板原文存到临时文件，跑完塞回去 | `restoreClipboard: true` | 每次 `run_params.clipChars: 862`、`clipboard: restored`（862 字符是提示词长度，还原动作确实执行了） |

**时段闸**（`gate.allowedHours`）已经做好但**没给你开**：现在配的是「不限时段」。想要它只在半夜干活，在 `company.prod.yaml` 的 `gate` 里加一行 `allowedHours: [23, 7]` 即可（支持跨午夜，`[23,7]` 就是 23 点到次日 7 点）。

## 3. 四道闸门分别干什么

| 闸门 | 一句话 | 配置项 | 被拦时说什么 |
|---|---|---|---|
| 人工暂停 | 你说停就停，排着的卡不丢 | `gate.pauseFile`（看板按钮就是写这个文件） | 「GUI 已人工暂停（时间）：原因，恢复后再派活」 |
| 时段 | 只在这些整点区间跑 | `gate.allowedHours: [from, to]` | 「现在 14:30 不在允许时段（23:00 - 07:00）」 |
| 静置 | 你刚动过键鼠就不抢 | `gate.requireIdleSec: 3` | 「你 N 秒前还在操作键鼠（要求静置 3 秒）」 |
| 锁屏 | 锁屏时不瞎按 | `gate.requireUnlocked: true` | 「当前会话已锁屏，GUI 按键会落到错误的窗口」 |

三个设计上的讲究，都是踩过才知道的：

1. **读不到键鼠空闲时间就放行，不拦。** 探测失败（比如换了机器、API 被改）时宁可多跑一次，也不要让活永远派不出去。
2. **暂停文件坏掉＝不暂停。** 打不开或内容不是合法 JSON 时按「没暂停」处理，否则一个坏文件能把整个席位永久冻住。
3. **闸门只决定「现在派不派」，不决定「任务完成没有」。** 完成永远只认磁盘文件（任务书 §8.3），这条铁律没被闸门绕过去。

## 4. `deferred` 和 `blocked` 为什么要分开（这条最容易误解）

生活化比喻：

- **`blocked` = 活干砸了。** 报告没写、校验和不匹配、窗口点错了——这种事要人来看，所以系统会出审批卡提醒你。
- **`deferred` = 排不上队。** 你正在打字、屏幕锁了、抢不到前台——**这不是失败**，是「等会儿再来」，卡退回排队，不出审批卡、不累加重试次数、不扣额度。

**为什么非分不可**：以前抢前台失败一律当 `blocked`。结果就是 Windows 随便挡一下，一天能给你堆一堆假警报审批卡，而活其实一次都没跑。今天真机上就被这个坑咬过（`T-6df64f3c` 两次 `blocked` + 一张 `AP-cd73cf56` 审批卡），改完这两单都是 `deferred` → 自动重排 → 跑成功。

## 5. 前台锁的根因（为什么以前老失败）

Windows 有一条安全规矩：**不是当前正在用的程序，去抢前台，系统会「静默拒绝」**——不报错、不弹窗，就是不理你。

所以现象特别迷惑人：脚本说「激活成功」、窗口标题也确实读到了，但你在屏幕上看，前台还是原来那个程序。

两条修法都落在 `scripts/win/kb.ps1` 里：

| 动作 | 修法 | 为什么这么修 |
|---|---|---|
| `activate`（抢前台） | 三次重试，每次之间**轻敲一下 Alt**，再核对标题 | 敲 Alt 是系统认可的「用户确实想切窗口」信号，敲完再抢就放行了 |
| `restorefocus`（还回去） | 同样是三次重试 + Alt，失败输出 `restore-failed: 想还「X」，当前是「Y」` | 还焦点也会被同一道锁挡住；而且**失败必须说出来**，不能假装还原了 |

**这次的证据比之前硬**：最后那一单 `focusRestored: "restored: WorkBuddy"`——下单前的前台是 WorkBuddy，跑完真的把焦点从豆包**抢回**了另一个程序。前几单报的是 `restored: 豆包工作`（那时候前台本来就是豆包），证不了「能不能把窗口从别处抢回来」。这次能证。

## 6. 为什么必须只有一份 GUI 席位

两个进程都带豆包席位 → 两个都去抢同一副键鼠 → 谁打的字进了哪个窗口说不清，可能把提示词打进你的聊天框。

做法：**启动前先占位**，占不到就不干。

| 情况 | 行为 |
|---|---|
| 没人占 | 写入 `work/gui-seat.json`（pid / 端口 / 配置路径），正常启动 |
| 有人占且进程活着 | 打印「GUI 席位已被另一个控制面占用（pid X，端口 3100…）」，**exit 5** |
| 有人占但进程已死 | 判定为陈迹，直接接管 |
| 停服务 | 标记 `released`，下次能立刻接管 |

**一个细节**：占位判定移到「建数据库」之前。不然被拒的实例会先在磁盘上留一个空库（之前真留过 `second.db`，已清）。

真机验证过：同配置再起一个实例 → `exit=5`，报出占用者的 pid 与端口。


## 12. P7 项目层：怎么建一个项目、产物落到哪（2026-11-16）

### 下单必带项目

看板「提一条需求」里的**项目**下拉现在是必选项；命令行这样写：

```bash
npm run task -- "译第八章，按工作流做初校" --project benny --wait
```

`--project` 不写时，只配了一个项目会自动填上并打印出来；配了多个项目就必须明说。不写项目、写错项目、项目缺规范，三种情况下单当场被拒，并列出可选项目。

### 建一个新项目（三步）

1. **改配置** `config/company.prod.yaml` 的 `projects` 段，加一条：

   ```yaml
   projects:
     你的项目id:
       displayName: 给人看的名字
       memoryLimit: 10          # 每次派活注入最近几条经验，0–50
       rootDir: D:/某盘/项目文件夹   # 产物落到哪：填了就是授权；不填＝产物只留公司
       deliverSubdir: 04-译稿      # 可选，落 rootDir 下这个子目录；不填＝落根目录
       deliverBlockers: ["YiTai*"] # 可选，这些进程开着就先不落盘，等它关掉再补
   ```

   `rootDir` 必须是**绝对路径**，`deliverSubdir` 只能是它下面的相对子目录（写绝对路径或带 `..` 会在启动时体检报错）。

2. **写规范** `work-prod/projects/你的项目id/project.yaml`。这是给 AI 员工看的长期规矩，派活时全文塞进 brief。人可以起草、AI 也能起草，但**要你拍板**。项目文件夹里已有的规矩不用抄进来——写清「权威文件在哪、冲突时以哪份为准」即可。

3. **重启常驻** `npm run win:stop && npm run win:start`（或 `npm run doctor:prod` 先体检）。

### 经验是怎么自动长出来的

员工交差时多写两个可选字段（`lessons` 踩过的坑、`nextHints` 下一单先做什么）。引擎在卡**真正 done** 时才校验并追加一行到 `work-prod/projects/<项目>/knowledge/memory.jsonl`——打回重做的不算数。下一单派活时，引擎把规范全文 + 最近几条经验一起塞进 brief。**AI 碰不到库，只能供料；落笔的是引擎。**

看板顶部的「项目」卡片能看到每个项目的规范状态、经验条数，展开能看最近三条，产物落点也写在上面。

### 产物什么时候落进项目文件夹

验收通过后引擎**复制**一份到 `rootDir`（+ `deliverSubdir`），**原件留在公司任务目录**。同名文件不覆盖，自动加任务号后缀。落盘前若 `deliverBlockers` 里的进程在跑（比如译台占着译稿），就先记 `deliver_deferred` 审计，等维护心跳重试，绝不硬写。每次落盘在公司侧 `projects/<项目>/deliveries.jsonl` 留一条清单（含校验和），和项目里那份可逐字节对账。

**要改落点**只改配置那一行，不改代码；**没配 rootDir** 的项目（例如自研开发 `aicompany-dev`）产物只在公司里，由人自己取。
