# 董事会看板改版（2026-11-18）：少一点流水账，多一点「现在该我拍板什么」

> 触发：董事会原话——「任务卡片列表太长了，显示近期任务就行了；审批放在显眼的地方，比如一个单独卡片里，有审批就右上角一个红色数字标记；整体界面优化，色调太暖了公司不严肃，你来美化。」
> 范围：只动 `src/web/board.html`（单文件，内联 CSS + JS）。服务端接口、引擎、任务流一律没碰。

## 1. 为什么要改

改版前的看板是三处硬伤叠在一起：

| 现象 | 实情 |
|---|---|
| 任务卡一屏铺不完 | `/api/tasks` 已累计 **77 张**，`renderTasks()` 把全量倒序平铺成一张表，翻旧账把「现在在发生什么」挤到看不见 |
| 审批藏得深 | 审批卡是「任务与汇报」页签里第 5 张卡，要先切页签、再往下滚；真正的待办只有一条黄条提示，看着像警告不像待办 |
| 色调太暖 | 米黄底（`--bg #F1EFE8`）、土黄线条（`#B4B2A9`）、黄条（`#FFF6E5`），像纸质便签板，不像公司控制台 |

## 2. 改成了什么

### 2.1 换肤：冷灰蓝 + 海军蓝（严肃向）

`:root` 全量换掉调色板：底 `#EDF0F4`、卡面纯白、线条 `#D6DDE7`、正文 `#16202B`、强调色 `#1E4E79`、顶栏深色带 `#131C26`、状态色收到「绿=成、蓝=在跑、橙=卡、红=坏」。

- 顶栏用深色带，左边 `AI` 方块品牌 + 「AICompany / 董事会看板」，右边是待办红点、SSE 状态、刷新。
- 表头 `th` 改灰底 + sticky，行 hover 淡蓝白（`#FAFBFD`），数字列用等宽字体（`font-variant-numeric: tabular-nums`）。
- 卡片圆角 8px + 轻阴影，指令台顶边 3px 海军蓝，变成「主控区」而不是一张普通卡。
- 顺手把散落各处的旧硬编码颜色（`#5F5E5A`、`#B4B2A9`）收进 CSS 变量。

### 2.2 待办：从一条黄条，变成「红点 + 常驻审批坞」

- 顶栏新增按钮 `#pending-jump`，内含 `#pending-badge`：**有单子就是红底白字数字，没有就灰 0**。任何标签页都看得见，点一下直接滚到能拍板的地方。
- 审批卡从「任务与汇报」页签里搬出来，独立成 `section.card.dock#approvals-card`，位置在指令台正下方（第二眼就能看到）。有单子时左侧红边 + 标题旁红色计数 `#approval-count`；**没有单子整张收起**，不占地方。
- 「挂起待决策」（`awaiting_decision`）仍留在任务页里，但它也算待办：数字一起计进顶栏红点，点红点会自动切到那一页并滚过去。
- 浏览器标签页标题也带前缀「（N 项待你拍板）」；「任务与汇报」页签文案变「任务与汇报 · N 待办」。
- 审批坞文案写死一句实话：「不点就一直停在这儿，公司不会自己往下走」——把引擎的真实行为摆在董事面前。

### 2.3 任务卡：默认只列最近 12 张

- `renderTasks()` 重写：先按 `createdAt` 倒序（老数据缺时间就退回库序倒序），`RECENT_TASKS = 12`，默认只画最近 12 张。
- 卡片顶部一条 `taskbar`：「共 77 张，显示最近 12 张」 + 右侧「看全部 77 张 / 只看最近 12 张」切换（`data-toggle-tasks`，事件委托，不重绑）。
- 列表区固定 `max-height: 560px` 内部滚动，表格头 sticky，翻页不会把整页顶下去。
- 保留原有「看结果 / 重派 / 取消」与卡号等宽字色，功能一个不少。

### 2.4 统计砖瘦身

原来 10 块，永远全显（含「已取消」「配额触顶」「唤醒次数」「协作空间」）。现在**常显 6 块**：任务卡 / 已完成 / 进行中 / 阻塞 / 待我拍板 / 挂起待决策；后三项（配额触顶、唤醒次数、协作空间）**只在 >0 时**才冒出来。待办两块可点，点了跳对应区域。

## 3. 没动的（测试契约）

`tests/p1.test.js` 要求页面含 `Tasks / Approvals / Inbox / id="mode" / id="addressedTo" / WorkThread / EventSource`；`p2` 要求 `plan-list / data-sched / 只跑一次 / /api/recurring`；`messages` 要求 `id="messages-list" / /api/messages`。所以标题写成「任务卡 · Tasks（最近）」「审批 · Approvals · 等你拍板」，英文锚点全部保留。

## 5. 已知限制

1. 「最近 12 张」按创建时间算，不按更新时间；一张很久以前建、最近刚被重派的卡会落在下面——要看它就点「看全部」。
2. 统计砖的「进行中」= `in_progress + in_review`，两态合并显示，细节去任务页看。
3. 审批坞的预览是页面内造结构看的，当时库里 0 单；真实有单时的文案排版由 `renderApprovals()` 渲染，字段与旧版一致。
4. 交互仍是「刷新 / SSE 推」，没有做成工作表那种内嵌编辑，董事会只需要拍板和看结果。

## 6. 追加（2026-11-18）：把「待验收」和「验收中」分开

董事会当场指出：**验收会话正在跑的时候，看板上还是写「待验收」**，看起来像没人管，直到验收出结论才变「已完成」。

查了状态机：`TASK_STATUSES` 是封闭枚举，`in_review` 一个状态同时承载「等审」和「正在审」；真正区分两者的信号是 **runs 表里那趟 `wakeReason='review_requested'` 的 running run**（`seatReview()` 叫席位起来审时就是这么记的）。引擎不改状态（加了 `reviewing` 就等于改协议，测试会拦），所以在看板这一层把语义补出来：

- `reviewRunFor(taskId)`：从已经拉回来的 `/api/runs` 里找这张卡正在跑的验收 run（只看 read-only 数据，不加接口）。
- 有这趟 run → 状态列显示 **「验收中」**（同一套 `s-in_review` 配色）+ 小字「`agentId` 正在审（N 分钟）」；「模式」列的小标签从「等 `x` 审」变成「`x` 审着」。
- 没有这趟 run → 仍是「待验收」，含义就是「真的在等人开审」。这时候如果该审的人 20 分钟不动，心跳会 `review_fallback_ceo` 转总经理；补审 5 次还不行就 `review_stuck` 出消息。

验证：内联 JS 语法 OK；页面 12 行任务卡正常渲染、console 无报错；契约测试 69/69。纯 `board.html` 改动，不重启控制面。
