## 一、你问的两个问题，先说结论

### 1. CEO 为什么不派活、自己去干代码？

**两个原因都成立，而且是叠加的：**

| 原因 | 具体是什么 |
|---|---|
| **它压根不是 CEO 席位** | 上一轮为了"能干活"，我把它配成了**执行席位**：`isCEO: false`、`capabilities: [execute]`。引擎里"是不是 CEO"决定了两件完全不同的事：执行席位只交完成报告，CEO 席位才被允许"拆卡派活 + 验收"。所以它**没有派活的权限**，只能自己干。 |
| **提示词也在叫它自己干** | 提示词第一句是"你是 AICompany 的**执行席位**，请用你的工具完成下面的任务"；员工名册也没给它——引擎只往下传了 `{id, isCEO}`，连"豆包能干什么"都没告诉它。它既不知道有员工，也没被告知"你只负责拆解和验收"。 |

一句话：**它当时是个"叫总经理的执行工"，不是总经理。**

### 2. 建议之后怎么新建项目？

之前确实**没有任何渠道**——项目只能手改 `config/company.prod.yaml`。现在有三条路，都通：

| 渠道 | 怎么用 |
|---|---|
| **看板 → 项目标签页 → 新建项目** | 填 id / 显示名 / 落盘目录 / 交付子目录 → 创建。立刻生效，不用重启。 |
| **CEO 建议 → 审批单点「通过」** | CEO 判断"该单开一个项目"时会出一张 `project_create` 审批卡（在「席位与审批」页）。点通过 = 自动建好目录 + 起步规范 + 记进配置；驳回则这活按一次性任务处理。 |
| **API** | `POST /api/projects {id, displayName, rootDir, deliverSubdir}` |

建项目时会做三件事：建 `work-prod/projects/<id>/`（含 `knowledge/`）、写一份**可编辑的起步 `project.yaml`**（已存在就**不覆盖**）、把条目写进 `config/runtime-overrides.json`（不动你手写的 YAML 注释，重启后仍在）。

## 二、这步到底改了什么

### A. CEO 换成真 agent，角色只有三件

`config/company.prod.yaml`：

```
ceo        → webhook-exec（mode: ceo）  总经理(真agent)：定方向 / 拆活派活 / 验收
ceo-agent  → webhook-exec（execute）    研发工位(真agent)：员工，能读盘能跑命令
doubao     → gui-template               豆包工作：员工，GUI 席位
interaction.defaultMode: delegate       默认「董事会 → CEO → 员工」
```

`mode: ceo` 是 webhook-exec 的第二种角色（同一个插件、不同的提示词与产出契约）：

- **提示词给全信息**：员工名册（谁、什么类型、能接什么难度、在不在岗）、现有项目清单（含落盘位置、有没有规范）、项目归属三选一规则、拆解要求、**严格 JSON 输出契约**；
- **只出 CEO 契约**：`task-create` / `review`，产出不合契约直接报错，绝不静默当普通员工收账；
- **验收轮换一套提示词**：告诉它产物目录和完成报告在哪，要求它**用工具真的去读**，再给 `verdict: pass|reject`。

### B. 引擎支持"真拆解"

| 能力 | 说明 |
|---|---|
| **一次拆多张卡** | CEO 输出 `tasks: [...]`（最多 8 张），引擎逐张建卡、逐张派活；有一张派不出去就整单挂起，不做"半单" |
| **CEO 改判项目** | 你下单不选项目时，CEO 可以在卡里写 `project: "benny"`，子卡就落到那个项目；写了不存在/没规范的项目会被拒并留审计 |
| **建议建项目** | 输出 `projectSuggestion` → 引擎出一张 `project_create` 审批单（同一张卡只出一张，不刷屏） |
| **拆解说明可见** | CEO 的 `summary` 写进审计（`ceo_plan`），同时挂在子卡上，看板任务列表里直接显示"CEO：…" |

### C. 执行席位不再抢 CEO 的判断

以前执行席位拿到的提示词里有"你自己判断项目归属"，现在改成一句事实说明："本卡没有项目归属，产物写在当前工作目录"。**判断归 CEO，干活归员工**，不重复决策。

### D. 顺手修掉三个真问题

1. **报告不落盘** → 执行席位交完活，adapter 现在把 `completion.json` 写到任务根目录，看门狗不会再报 `done_without_report`。
2. **同一张卡第二轮投不进去** → webhook 插件原来对同名 taskId 直接返回旧结果（返工/验收/重试都会变成空转）。现在改成：正在跑 → 拒绝并发投递；已跑完 → 清空上一轮文本、复用同一个会话再跑一轮。
3. **CEO 验收没有证据** → 验收提示词直接给产物目录和报告路径，CEO 必须去读文件，不能只看承接人的自述。

## 三、真机验证（生产环境，不是模拟）

用看板 API 下了一单（**不选项目**）：

> "帮我看一下 work-prod/tasks 里最近完成的那张卡的 output 目录，产物到底齐不齐、有没有空的。给我一句结论就行，别改任何文件。"

发生了什么：

1. 父卡 `T-81114618` 派给 CEO → CEO 跑一轮（18 秒），产出：项目归属判断（一次性只读巡检，不归 benny 也不建议新建）+ 1 张卡 + 派给 `ceo-agent`；
2. 子卡 `T-dbbd7e4a` 自动建、自动派给研发工位 → 员工真的去读盘、盘点目录（跑了 3 分钟）；
3. 员工交活 → 自动进 `in_review` → 自动叫 CEO 验收；
4. CEO 验收时**自己重算了三个文件的 sha256**、比了各卡 mtime、还发现"父卡 T-81114618 在 tasks 下没有目录"这件事并如实标注 → `verdict: pass`；
5. 卡 `done`。

审计链（可直接在「运行与审计」里查到）：

```
human   create_task  T-81114618
ceo     wake         issue_assigned:R-f36220b5
ceo     run_params   {"transport":"webhook-exec","mode":"ceo","sessionId":"aiceo-ceo-T-81114618-plan","turn":1}
ceo     ceo_plan     这是一次性只读巡检，不归档到 benny…派 ceo-agent 以一张只读卡完成，只查不改。
```

测试：**279/279 全绿**（新增 CEO 模式 4 条、插件重投 1 条、新建项目 2 条、项目 API 4 条）。

## 四、你现在可以怎么用

1. 打开 `http://127.0.0.1:3100/`，在最大的输入框里写需求，**不用选项目**，点「下达指令」；
2. CEO 会先判断归属、再拆卡派活；卡上会显示它的一句说明；
3. 员工干完 → CEO 自动验收 → 通过就 `done`，打回就返工一次（第二次打回转人审）；
4. 想新建项目：项目标签页的表单，或等 CEO 建议后点「通过」；
5. 想跳过 CEO 直接找某个员工：把模式切到 `direct`，在「交付给」里点名（这是"直投"的语义，不是日常路径）。

## 五、已知边界（如实说）

1. **CEO 现在能判断、能派活、能验收，但仍不能自己建项目** —— 只能建议，建项目要你点一下。这是故意的安全边界（防它乱建污染配置）。
2. **员工能力不均衡**：研发工位（真 agent）能改代码、跑命令；豆包是 GUI 席位（抢键鼠、慢）。CEO 会按类型挑，但如果豆包窗口没开，那张卡会被闸门拦下、等心跳重投，不会丢。
3. **多卡拆解没做"卡间依赖"**：拆出来的卡是并行的，CEO 需要在 instructions 里写清"等前一张"，否则可能并行干。要做严格串行得加依赖字段，属于下一步。
4. **CEO 跑一轮要 15~90 秒，验收要 1~5 分钟**：真读盘就是这个代价，不是卡住了。
