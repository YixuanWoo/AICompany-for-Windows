## ① 这步到底是咋回事（背景）

你（董事会）提了两点体验问题：

1. **项目不该必选**：给 CEO 派活儿，应该由 CEO 自己判断这是新项目、老项目、还是一次性任务，需要的话自己新建或选已有项目。原来下单强制选项目，"不那么优雅"。
2. **界面中心搞反了**：跟 CEO 对话（下指令）是最重要的，原来却挤在左边 330px 的小输入框里；一堆任务/状态卡片反而占着大地方。你要把下单窗口做成视觉中心，其他数据挪到旁边或标签页。

## ② 为什么要改

- 项目必选是早期 P7 定的规矩（"不靠 CEO 猜项目，猜错代价大"）。但**现在 CEO 已经是能读盘、能执行的真 agent 了**——它完全有能力看懂任务、判断归属，再逼人选项目确实是多余的动作。
- 董事会的核心动作就是"下指令 + 看汇报",这个入口必须一眼就位、打字舒服；看板数据是被查阅的次要信息，不该抢 C 位。
